# 백업 운영 도구 — 2026-10-03

일회성 시험 코드를 정리해 D1 내보내기와 로컬 검증을 한 명령으로 수행할 수 있게 했다. 이 도구는 기존 사이트, DNS, 결제, 원격 DB 데이터를 변경하지 않는다. 자동 예약 실행이나 외부 저장소 전송은 아직 설정하지 않았다.

## 실행

Windows PowerShell에서 저장소 밖의 보호된 백업 폴더를 먼저 준비한 뒤 실행한다.

```powershell
./scripts/backup-d1.ps1 -Destination <보호된-백업폴더> -NodePath <node.exe> -WranglerPath <wrangler.js>
```

현재 검수 배포 설정에 지정된 medihelpers-staging DB를 export한다. 목적지는 저장소 밖이어야 하고 junction/symlink 경로는 거부한다. 매번 시간과 무작위 ID가 있는 새 이름을 사용한다. 기존 정상 백업을 삭제하거나 덮어쓰지 않는다. SQL과 내보내기 로그에는 개인정보 또는 일시적인 다운로드 주소가 포함될 수 있으므로 공개 저장소에 올리지 않는다.

내보내기에 성공해도 검증을 통과하기 전에는 정상 백업으로 표시하지 않는다. `.verified.json`이 없는 파일은 검증 완료 백업이 아니다. 실패 시 마지막 정상 백업을 유지한다. 인증 실패는 성공으로 삼지 않으며 자동으로 로그인이나 키 변경을 시도하지 않는다.

다른 SQL 백업을 별도로 검증하려면 다음을 사용한다.

```text
python scripts/verify-d1-backup.py <원본.sql> <새로운-manifest.json>
```

## 검증 내용

- 메모리 SQLite에서만 로드하며 외부 DB 연결, 확장 로딩, 외부 파일 접근 함수와 위험한 PRAGMA를 차단한다.
- SQLite integrity_check와 전체 foreign_key_check, 테이블별 행 수를 확인한다.
- 업로드 메타데이터, 파일 크기, 청크 순서·길이, 누락/초과 청크, 원본 SHA256을 검사한다.
- 잘못된 SQL/스키마, 손상 파일, 외래키 오류는 정상 manifest를 만들지 않는다. 기존 manifest 덮어쓰기도 거부한다.
- manifest에는 백업 해시·크기·테이블별 개수·파일 검사 집계만 저장하며 회원/결제 원문은 출력하지 않는다.

## 실제 확인

12개 회귀검사 통과. 이전 원격 복원 리허설 SQL 36,187,921바이트(47테이블, 합성 파일2개·15MiB)를 이 도구로 재검증했다. 해시 `354ed49d528a429cf06580ac16828fb47266cef1e936a0a0be4ab0fed23f2087` 일치.

현재 검수 DB도 새 도구로 다시 내보내 검증했다. 47테이블, 4,727,830바이트, 파일0개, 해시 `813ee0b8d2cc49b5955bef02c547562c9420ea71587243ee89db9a2879fcc1ca`로 이전 정상 백업과 일치했다. 첫 시도는 Cloudflare 인증10000 오류로 실패 처리됐으며, 새 파일명을 쓰는 두 번째 시도에서 성공했다. 실패 로그와 성공 manifest를 모두 Git 밖 감사 폴더에 보존했다.

이 검사는 백업 내부 무결성 확인이다. 랭크업 전체 자료가 수집됐거나 최신 증분이 반영됐다는 증명은 아니다. 실제 복원은 [격리 복원 실행서](REMOTE_RESTORE_20261003.md)를 따른다. 외부 자동 백업을 운영하려면 독립된 저장 위치, 인증 유지 방식, 실패 알림·보관 기간이 추가로 필요하다. 현재 자동 보호는 D1 Time Travel이고 독립된 사본은 이 도구로 수동 확보한 로컬 SQL이다.
