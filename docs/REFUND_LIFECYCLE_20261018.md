# 환불 요청·부분 환불·결과 안내 — 2026-10-18

## 운영 방식

회원은 **마이페이지 → 결제·사용이력 → 환불 요청**에서 사유를 입력한다. 요청 금액 0은 금액 미확정을 뜻한다. 접수만으로 카드가 취소되지 않는다. 요청 중에는 해당 주문의 새 열람권 소비를 보류하며 이미 유료로 열람한 이력은 유지한다.

운영자는 **관리자 → 결제·환불 원장 → 환불 요청 대기**에서 주문을 선택한다. 실제 취소는 기존 **이니시스 관리자**에서 먼저 처리한다. 홈페이지의 `취소 완료 기록 반영`은 PG 취소 API를 호출하지 않는다. `INICIS_REFUND_MODE=manual`, `INICIS_REFUNDS_ENABLED=false`를 유지한다.

## 부분 환불 절차

1. 원 주문·승인 TID·결제액·누적 환불·사용 내역을 확인한다. 광고 이용 기간이나 사용한 열람권의 공제 금액은 계약 조건과 사실관계로 산정한다. 시스템이 자동으로 환불 자격이나 공제액을 결정하지 않는다.
2. 이니시스 관리자에서 취소를 완료한 뒤 **원 TID, 취소 TID, 이번 취소 금액, 취소 후 잔액, 취소 완료 시각(KST)**을 대조한다. 부분 취소에는 원 TID와 다른 개별 취소 TID가 필요하다. [이니시스 공식 취소 API 문서](https://manual.inicis.com/pay/cancel.html)의 부분 취소 거래 구분을 따른다.
3. 내부 확인 근거와 **회원에게 공개할 처리 결과·금액 산정 근거**를 각각 입력한다. 내부 근거에 카드번호·비밀키를 적지 않는다. 이번 금액과 취소 후 잔액의 합계는 홈페이지의 현재 잔액과 같아야 한다.
4. `취소 완료 기록 반영` 후 원장·광고/열람권·알림이 함께 저장된 결과를 새로고침해 확인한다. 추가 부분 환불이나 남은 금액 전액 환불은 새 요청으로 처리한다.

부분 환불은 **미사용 서비스 종료 방식**이다. 해당 주문의 남은 광고 노출·새 열람권 소비를 종료하고 기존 유료 열람은 보존한다. 누적 전액 환불은 해당 주문의 모든 열람 권한을 회수한다. 다른 유효 결제로 구매한 광고·열람권은 유지한다. 기존 열람권의 무기한 정책을 임의의 만료일로 바꾸지 않는다.

이미 이니시스에서 취소한 뒤 홈페이지 저장이 실패하면 **카드를 다시 취소하지 않는다.** 홈페이지를 새로고침해 원장 반영 여부를 확인하고, 미반영일 때만 같은 취소 증빙으로 기록을 재시도한다. 잘못된 기록의 임의 덮어쓰기나 반려는 금지한다.

## 반려·회원 안내

- 반려 사유는 5~1,000자 필수다. 이용 내역·판단 근거·추가 확인 방법을 구체적으로 적는다. 이미 PG 취소가 완료된 거래는 반려하지 않는다.
- 반려는 결제액과 이용 권한을 유지하며, 환불 요청으로 보류됐던 새 열람권 사용이 가능해진다. 추가 증빙이 있으면 다시 요청할 수 있다.
- 회원의 결제 내역에는 접수/처리 시각, 신청 사유, 확정 환불액, 누적 환불액과 잔액, 반려 사유/처리 안내가 표시된다. `처리 결과 새로고침`으로 갱신한다.
- 처리 완료와 반려는 **홈페이지 알림함·활동 기록**에도 남고 해당 결제 내역으로 연결된다. 이메일·SMS 자동 발송은 구현/발송하지 않았다. 홈페이지 반영과 카드사의 입금·한도 복원 시점은 다를 수 있다.

## 안전장치와 호환성

회원 본인 주문만 요청/조회 가능하고 처리는 운영자에게만 허용한다. 교차 출처 요청, 중복 접수·동시 처리, 잔액 초과, 이미 사용한 취소 TID, 승인 거래 불일치, 금액 원장 불일치를 차단한다. 처리 원장·권한·확인 이벤트·회원 알림은 하나의 D1 트랜잭션으로 저장한다. 저장 실패 시 전부 롤백한다. 공개 API에는 내부 확인 근거와 PG 취소 TID를 반환하지 않는다.

기존 DB의 환불 status 제약은 `rejected`를 허용하지 않는다. 기존 테이블을 재작성하지 않고 `cancelled`와 변경 불가 `refund_rejected` 이벤트를 함께 저장하며, 조회 API에서 명확한 `rejected` 상태로 매핑한다. 반복 부분 취소의 각 확인 이벤트와 원장 CSV는 취소별 TID·금액·시각을 독립적으로 보존한다.
