## 관리자에서 확인한 사실

- MID `UPmedihelp`, 기본정보의 중지구분은 `사용`, 홈페이지는 `medihelpers.co.kr`이다.
- 결제수단 정보에서 신용카드·실시간계좌이체·가상계좌 모두 `사용`, 사용가능일자는 2017-10-19로 표시됐다. 휴대폰은 미사용이다.
- 카드사 등록현황은 하나·롯데·현대·국민계열·BC·삼성·신한·NH·하나SK에 등록으로 표시됐다. 우리카드 행은 상태가 비어 있어 별도 등록 완료로 세지 않았다.
- 현재 취소한도는 0원이다. 상세 설명은 지급예정액(D+2 이후), 당일 승인에서 취소를 뺀 금액, 지급보류액과 에스크로 미정산액을 반영한다고 명시한다. 따라서 이 표시만으로 신규 시험 거래의 당일 취소 불가를 단정할 수 없고, 반대로 실제 취소 성공으로 인정할 수도 없다.
- 가상계좌는 실시간 통보·건별채번·윈도우버전·TX방식으로 표시되며 계약 화면의 입금통보URL/PORT는 빈 값이다. 거래 요청에서 URL을 지정할 가능성이 있으므로 기존 통보가 없다고 단정하지 않는다. 기존 설정을 변경하지 않았다. 새 사이트에서 가상계좌를 열려면 기존 지연 입금의 전달 경로를 별도로 확인해야 한다.
- FAQ/계약서다운로드 메뉴는 본문이 빈 화면으로 열려 현재 계약서 원문을 확보하지 못했다. 계약 동의·변경·키 재발급·거래 취소는 수행하지 않았다.

## 호스팅 이전 판단과 남은 조건

[이니시스 공식 FAQ](https://www.inicis.com/blog/archives/category/cs/cs_best/%EB%AA%A8%EB%93%88%EC%97%B0%EB%8F%99-faq/page/14)는 동일 사업자의 여러 사이트에 하나의 MID를 쓸 수 있다는 일반 안내와 서버 이전 시 연결/모듈 지원 점검을 제시한다. 이것은 기존 MID 재사용의 일반적인 가능성에 대한 근거이며, HOSTrankup 계약의 개별 조건이나 Cloudflare 요청 IP 처리를 승인하는 답변은 아니다.

**이니시스 로그인만으로 남은 실결제 조건이 충족되지는 않았다.** 현재 화면과 공개 규격에서 Workers의 INIAPI clientIp 값을 확정하지 못했다. 요청 서버의 IP 대신 방문자 IP, 기존 랭크업 IP, 예제 IP를 넣지 않는다. 해당 처리 근거와 계약 확인, 사용자 카드 인증을 포함한 실제 승인/취소가 필요하다. 기존 고객 거래를 시험에 사용하지 않는다.

운영자 비밀번호 설정 보류를 재개할 수 있는지 한 번 요청했다. 사용자 직접 설정과 실제 세 역할 검수 없이 배포 게이트를 통과했다고 기록하지 않는다. 랭크업 전체 백업/최신 증분도 미완료다. 전체 작업표의 6단계는 그대로 열려 있다.
