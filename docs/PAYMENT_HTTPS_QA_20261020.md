기존 로컬 검수에서 막혔던 외부 PG → 루프백 복귀 제한은 별도 HTTPS 서버에서 발생하지 않았다. 브라우저 네트워크 보호나 HTTPS 검증을 해제하지 않았다.

이니시스 공개 테스트 상점 `INIpayTest`와 합성 병원 계정만 사용했다. 카드정보 입력, PG 약관 동의, 실제 승인·환불은 진행하지 않았다. 여기서 **재결제 검수는 기존 주문의 결제창 재개까지**를 뜻하며 실제 재승인 성공을 뜻하지 않는다. 실제 iOS/Android 앱카드 복귀도 미검증이다.

테스트 Worker는 일반 회원가입·임의 입력 기능과 폼·JSON 형태 PG 승인 요청을 모두 403으로 차단하고, JSON의 checkOnly 상태 조회만 허용한다. 최종 보호 설정에서도 브라우저 상태 조회 정상 안내를 재확인했다. 익명 주문 재개는 401이었다. 합성 계정 초기화용 임시 경로는 초기화 직후 제거했다. 테스트 계정 비밀번호는 무작위로 생성해 로컬 비공개 파일에만 보관했으며 저장소·문서·공개 응답에 넣지 않았다.

로그인 페이지는 HTTPS 200, no-store, noindex/nofollow였으며 `/api/payment-close`는 200·no-store와 테스트 환경의 공식 닫기 스크립트를 반환했다. 요청한 별도 테스트 주소는 검토용으로 남겨두고 **2026-10-22 13:30 KST부터 자동으로 요청을 거절**한다. 이 제한은 테스트 Worker에만 적용된다.
