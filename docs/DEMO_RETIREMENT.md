# 정식 오픈 전 예시 정리

현재는 예시를 유지한다. 정식 오픈 시 제거한다는 사용자 결정이며 지금 실제 회원이나 게시물을 삭제하는 지시가 아니다.

## 제거 대상과 순서

1. `src/data.js`의 정적 talent 배열(인재 코드 MH-D-/MH-N-/MH-R-/MH-P-), `demoTalentScenarios.js`의 가상 연락처, 서버 testTalentDetails와 클라이언트의 정적 예시 병합을 함께 제거한다. 정상 DB `seeker-*` 인재 경로를 유지한다.
2. 사이트의 다른 예시 채용공고·병원 이미지·테스트 계정도 목록을 먼저 대조한다. 테스트 역할 전환은 현재 사용자 요청에 따라 유지 중이다.
3. 실제 PG 활성화 전 테스트 자료를 백업하고 예시 ID를 참조한 가상 주문·권한·열람/감사 이력을 관계별로 검토한다. `payment_orders.metadata_json.talentId`, `talent_unlocks.talent_id`, `access_audit_logs.subject_ref`를 기준으로 대상 목록을 확정한다. 실제 회원 원장이나 ID가 불분명한 행을 제목/이메일 문자열만으로 일괄 삭제하지 않는다.
4. 수량제 팩은 여러 인재에 사용될 수 있으므로 예시 권한만 지우고 잔액을 임의 증가시키지 않는다. 테스트 주문에 속한 풀과 실제 주문·소비를 구분해 함께 정리한다. 테스트 병원과 의사의 실제 작성 자료가 섞여 있으면 계정 통째 삭제 대신 대상별로 처리한다.
5. 정리 후 익명·의료인·병원·관리자 별 목록, 연락처 공개/비공개, 단건/팩/재열람, 취소/실패, 수량 이력을 다시 검증한다. 공개 예시와 비공개 예시가 운영에 남아 있지 않은지 확인한다.

현재 PAYMENT_LIVE=true 또는 실결제 키 설정 시 서버에서 예시 결제와 상세를 차단하지만, 이는 정적 예시 목록과 테스트 원장을 삭제한 상태를 뜻하지 않는다. 오픈 체크리스트로 별도 완료한다.
