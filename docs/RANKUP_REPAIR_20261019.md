## 원본 소스를 수정할 수 있는가

현재 관리자의 디자인 메뉴는 탑 디자인·정렬 선택을 제공하며 서버 PHP 편집기는 확인되지 않았다. 공고 HTML 편집은 가능해서 위 수정은 실제 반영했다. 현재 PC의 작업본은 보존된 신규 앱이고 랭크업 원본 PHP 저장소가 아니다. 대상 작업 폴더에서 FTP/SFTP 설정 파일이나 원본 PHP는 발견하지 못했다.

랭크업 공식 안내는 독립형 솔루션의 원본 제공·FTP를 통한 프로그램 수정을 설명한다. 다만 메디헬퍼스의 개별 계약 유형과 실제 FTP/DB 권한은 미확인이다. 관리자 로그인만으로 서버 파일 권한까지 확보됐다고 판단하지 않는다.

- [공식 FTP·원본 수정 안내](https://rankup.co.kr/rankup_faq/faq_view.html?no=127)
- [공식 디자인·프로그램 수정 안내](https://rankup.co.kr/rankup_faq/faq_view.html?keyword=4&no=13&page=2)
- [상품별 FTP/DB·소스 제공 비교](https://www.rankup.co.kr/etc/service_info.html)

원본 파일·DB 백업과 접속 권한이 확보되면 PHP 버전·세션 초기화·인증/PG 반환 흐름을 확인한 뒤 최소 범위로 수정한다. `PHPSESSID`의 속성 누락과 `rbUser` 발급을 확인했지만 `rbUser`가 인증용인지 통계용인지는 미확정이다. 공개 JS 9개에서 이 두 이름의 직접 참조는 발견하지 못했으며 서버 전체 의존성 검사를 대신하지 않는다. 쿠키를 무조건 같은 SameSite 정책으로 바꿔 PG 반환을 손상시키지 않는다.

## 끝까지 검수하기 위해 필요한 것

1. 랭크업 호스팅 관리 또는 FTP/SFTP/DB 접근과 정상 원본 백업. 사용자는 접속 정보를 모른다고 답변했다. 공급사에 요청할 문구를 준비했으며 발송하지 않았다.
2. 소유자가 동의한 기존 개인회원·병원회원 계정으로 직접 로그인. 기존 계정 비밀번호를 바꾸거나 다른 회원으로 대리 로그인하지 않았다. 새 검수 계정을 만들어 성공해도 기존 회원 비밀번호 유지까지 증명하는 것은 아니다.
3. 사용자가 진행하는 실제 검수 결제와 취소. 이후 주문·승인번호·결제액·상품 지급·취소 원장과 PG 내역을 대조해야 한다. 결제 한도·테스트 계정·실제 거래는 아직 정해지지 않았다.

현재 자동으로 완료 가능한 수정을 끝냈지만, 전체 3문제 해결이나 기존 회원/실결제 정상 동작 완료로 보고하지 않는다. 랭크업 원본 운영·도메인·기존 PG 키는 유지했다.

문서 18개 상대 링크 436개·`git diff --check`·보존 신규 앱의 `npm run build`가 통과했다. 새 앱 전체 단위검사를 재실행한 결과가 아니며, 랭크업의 검증 근거는 위 운영 화면과 폼 대조다. 문서만 기준 GitHub와 Sites 미러에 보관하고 신규 앱을 배포하지 않는다.
