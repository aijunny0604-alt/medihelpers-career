# 카드 결제와 이니시스 관리자 환불 운영 — 2026-10-09

사용자가 **홈페이지에서 카드 결제를 받고, 환불은 기존 이니시스 관리자에서 처리한 뒤 홈페이지에 반영하는 방식**을 승인했다. 기준 소스 4e0a009에서 구현했다. 자동 조회·일반 환불용 clientIp 해결은 이 운영 방식의 오픈 조건에서 분리한다. Oracle 가입·고정 IP 서버·랭크업 중계·외부 문의를 추가하지 않는다.

## 운영 순서

1. 회원의 환불 요청을 홈페이지 관리자 ‘결제 · 환불 원장’에서 확인한다. 주문번호, 원 거래번호(TID), 상품과 금액을 대조한다.
2. 기존 이니시스 관리자에 로그인하여 같은 거래를 조회하고, 환불 조건을 검토한 운영자가 **전액 취소를 완료**한다. 취소 요청 중·실패 상태를 완료로 취급하지 않는다.
3. 홈페이지의 해당 환불 요청에서 원 TID, 전액 취소 금액, 실제 취소 완료 시각, 확인 근거를 입력한다. 원 거래와 대조했다는 확인란을 선택하고 ‘취소 완료 기록 반영’을 누른다. 키·카드번호·개인정보 원문을 확인 근거에 넣지 않는다.
4. 확인창을 승인하면 주문·환불·거래 원장·감사 기록과 이용 권한 회수가 하나의 DB 트랜잭션으로 저장된다. 이는 카드 취소를 새로 요청하는 버튼이 아니다.
5. 목록을 새로고침하여 전액 환불 상태, 확인자·취소 시각·근거와 권한 회수를 확인한다. 이니시스 취소 내역과 홈페이지 환불 원장을 일별로 대조한다. 두 시스템 사이에는 자동 동기화가 없으므로 PG 취소 후 홈페이지 반영을 같은 업무에서 완료한다.

부분 취소, 기존 자동 취소 처리 중/결과 불명 거래, 금액이 다른 거래는 이 화면에서 확정할 수 없다. 별도 대사 후 처리하며 전액 취소로 잘못 입력하지 않는다. 이니시스에서 아직 취소하지 않은 요청만 반려할 수 있다. PG 취소 후 홈페이지 저장이 실패하면 카드 취소를 다시 누르지 말고 원장을 새로고침한 뒤 기록 반영만 재시도한다.

## 구현과 안전장치

- `INICIS_REFUND_MODE=manual`, `INICIS_REFUNDS_ENABLED=false`를 명시한 환경에서만 동작한다. 이번 작업에서는 원격 설정을 바꾸지 않았다. 설정 누락 시 수동 반영은 차단된다.
- 관리자 인증·동일 출처·검수 읽기 전용/점검 모드를 유지한다. 결제 승인을 수동으로 만들어내는 기능은 추가하지 않았다.
- 단일 성공 이니시스 카드 승인, 원 TID 및 전액 금액, paid 주문/requested 환불, 기존 성공 환불 없음, 승인 이후의 취소 시각을 확인한다. 부분 요청을 전액으로 덮어쓰지 않는다.
- DB batch의 첫 INSERT가 주문별 유일한 취소 처리권을 확보하고 현재 상태를 다시 검증한다. 중복·경합·기존 자동 환불 claim은 전체 트랜잭션을 실패시킨다. 원장이나 감사 기록 저장 실패 시 권한 회수까지 모두 롤백한다.
- 단건 열람권과 팩에서 발급한 열람권을 제거하고 남은 크레딧을 소진한다. 해당 광고의 다른 유효 paid 주문이 있으면 그 광고 노출은 유지한다.
- `inicis_manual_refund_recorded` 이벤트에 확인자, 시각, TID, 금액, 근거를 남긴다. `verification=operator_attestation`이며 PG API로 검증한 결과라고 표시하지 않는다. 관리자 원장에서 확인 기록을 다시 읽을 수 있다.
- 자동 승인 실패 시 필요한 망취소 처리는 기존 구현을 유지한다. 일반 고객 환불을 망취소로 대체하지 않는다.

## 검증 결과와 배포 범위

격리 SQLite/생성 Worker에서 신규 59개 검사 통과. 기존 포함 18묶음 총 1,573개, 일반/Cloudflare 빌드와 diff 검사 통과. 권한 거부, 설정 충돌, 잘못된 증거, 동시 3회 요청, 실패 후 롤백·재시도, 광고의 다른 유효 주문 보존, 단건/팩 권리 회수, 감사 근거 재조회, PG 네트워크 요청 0을 확인했다.

로컬 합성 관리자 화면에서 입력 안내·확인창·저장·새로고침 후 전액 환불과 감사 기록 표시를 확인했다. 날짜 입력값 보존과 긴 거래번호 줄바꿈, 한국 시각 표시를 보완했다. 원격 실제 계정 로그인이나 실카드 시험을 대신하지 않는다.

GitHub 기준 브랜치와 Sites 소스 미러에 같은 소스를 반영한다. 실제 Worker는 이전 확인 버전 `2b96835c-1d77-4eb9-942f-c6d19aed3286`/앱 `82b1201` 상태에서 이번 재배포 없음. 운영 관리자 비밀번호 설정은 사용자 보류를 유지한다. 실제 세 역할 로그인, 실카드 승인 → 관리자 취소 → 홈페이지 원장/권한 대사, 이전 회원·공고 인수와 최종 전환 검수는 미완료다. 정식 도메인·운영 DB·기존 PG 키·랭크업은 변경하지 않았다.

## 공식 규격 근거

[이니시스 PC 웹결제](https://manual.inicis.com/pay/stdpay_pc.html)의 승인·예외 망취소 요청에는 INIAPI의 clientIp 필드가 없다. [방화벽 안내](https://www.inicis.com/blog/archives/121212)는 상점 IP 사전 등록이 필요하지 않다고 안내한다. 이 사실은 기존 MID의 새 사이트 실제 승인을 검증했다는 의미가 아니다. 일반 취소 API의 서버 IP 문제는 향후 자동 환불 도입 때 별도로 해결한다.

## 날짜별 원장 대조 추가

관리자 결제·환불 원장의 CSV 다운로드로 한국 날짜별 승인·취소를 대조할 수 있다. 홈페이지 기록 날짜와 PG 취소 날짜가 다를 수 있으므로 두 시각을 함께 확인한다. 이니시스에서만 처리한 취소는 자동 수집되지 않는다. [조회 범위와 검증](PAYMENT_LEDGER_EXPORT_20261009.md)을 따라 양쪽 원 TID·금액·상태를 확인한다. 추가 후 전체 검사 수는 1,589개다.

## 미확인 거래 우선 확인

[결제 결과 확인 목록](PAYMENT_EXCEPTIONS_20261009.md)에 승인/취소 결과 불명 거래와 PG 취소 확인 후 홈페이지 반영 대기를 표시한다. 결제 성공 CSV에 없는 거래도 있으므로 목록을 먼저 확인한다. 정상 진행 중일 수 있으며 PG 상태를 대조하기 전 중복 처리하지 않는다.

## 입력 시간대 통일

수동 환불 취소 완료 시각은 이니시스 내역의 한국 시각(KST)을 입력한다. 현재 기기 시간대를 사용하지 않고 +09:00으로 변환하며 서버는 UTC ISO를 보존한다. 회원 결제일과 알림도 한국 시각 기준이다. [일괄 검수](REMAINING_BATCH_20261009.md).
