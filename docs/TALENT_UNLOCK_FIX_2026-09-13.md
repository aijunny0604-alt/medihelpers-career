# 예시 이력서 열람·실제 열람권 후속 검수

## 사용자 문제와 원인

배포 357에서 `MH-D-2048` 예시 프로필에 실제 이력서 API를 호출했다. 서버에는 이 예시의 원본 이력서가 없으므로 404를 반환했고, 준비된 예시 경력·자기소개도 `unlock.unlocked` 조건에 막혀 화면에 나오지 않았다. 사용자는 ‘열람권 구매 불가’를 서비스 고장으로 받아들였다. 기존의 예시 구매 차단은 유지하되, 예시 상세를 볼 수 있는 별도 미리보기가 필요했다.

## 수정 범위

- 명시적인 정적 예시는 경력·학력·자기소개를 무료 미리보기로 표시한다. 가상 인물임을 알리고 결제·차감 API를 호출하지 않는다. 실명·전화·이메일은 예시 상세에 복사하지 않는다.
- 실제 DB 프로필은 예시 플래그를 받아들이지 않는다. 실제 이력서는 서버의 성공한 권한 응답만 표시한다. 본인 무료, 관리자 열람, 병원 구매, 작성자의 연락처 공개 선택은 유지한다.
- 로딩, 삭제/비공개 404, 한도 429, 통신/서버 오류를 구분한다. 통신 오류에 구매 불가 또는 재구매 버튼을 표시하지 않고 ‘다시 불러오기’를 제공한다.
- 이력서와 로그인 계정이 바뀌면 이전 상세 상태를 초기화하고 진행 중 요청을 취소한다. 일반회원에게 병원 전용 구매 버튼을 노출하지 않는다.
- 병원 결제 정보 누락 시 비활성 버튼만 남기지 않고 마이페이지 회원정보 수정 경로를 제공한다.
- 실제 구직자에게 진료과별 예시 강점·선호를 임의로 붙이지 않는다. ‘상담에서 확인한 범위’는 앞으로 확인할 내용으로 정정한다.
- 테스트 계정 전환, 관리자 정책, 가격, 크레딧 수량, 개인정보 보호책임자는 변경하지 않는다. DB 스키마·운영 바인딩 변경 없음.
