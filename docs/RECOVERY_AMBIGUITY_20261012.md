# 아이디 찾기 중복 일치 처리 수정

이름과 전화번호가 동일한 계정이 복수일 때 LIMIT1/first가 첫 계정을 임의 선택했다. 등록된 메일함으로만 발송되어 요청자에게 직접 아이디가 노출되지는 않지만, 의도한 계정이 아닌 안내가 발송될 수 있었다.

최대2건을 조회하고 정확히1건일 때만 발송 대상으로 선택하도록 수정했다. 공개202 응답은 일치0/1/복수 모두 동일하게 유지한다. 기존 아이디를 알고 있는 경우의 정확한 아이디 기반 비밀번호 복구는 변경하지 않는다. 관리자 권한·회원 상태도 바꾸지 않는다.

생성 Worker와 메모리 SQLite에서 동일 이름/번호2계정을 만든 뒤 발송기를 가짜 함수로 바꿔 검증했다. 수정 전 발송1건으로 재현 실패, 수정 후 중복0건·미일치0건·유일일치1건 및 정확한 아이디/수신처 확인. 실제 이메일 발송과 고객 데이터 사용 없음. 새10검사 포함 전체19묶음1,789개 및 두 빌드 통과.

최초 수정 시에는 후보였으며 아래 후속 원격 검수 후 검수 Worker에 배포했다. AGENTS.md의 로그인·권한 변경에 대한 새 세션 의료인/병원/관리자 보호 API 검수 조건에 따라 실제 배포 전 역할별 확인을 별도로 남긴다. 로컬 합성 역할 회귀 통과를 실제 이전 회원 로그인 완료라고 보고하지 않는다.

보호 로그: recovery-ambiguity-before-20261012.log / recovery-ambiguity-after-20261012.log. 초기 테스트 삽입 시 Python 기본 인코딩 오류가 발생했지만 UTF8로 다시 작성한 뒤 수정 전 실패를 확인했다. DNS/원격DB/회원권한/PG 변경 없음.
