## 기존 아이디 로그인 구현

- DB 0019의 `auth_login_aliases`는 검증된 이전 계정에만 연결한다. 공개 회원가입으로 기존 아이디를 선점할 수 없다.
- 이메일 로그인과 기존 아이디 로그인은 같은 계정 잠금 횟수·정지 상태를 사용한다. 세션은 정규 계정 이메일과 역할로 생성된다.
- 이메일 형태의 아이디는 다른 이메일 로그인을 가로챌 수 없다. 기존 아이디는 대소문자를 정확히 구분한다.
- 기존 해시 검증이 가능한 짧은 비밀번호는 로그인 입력 단계에서 차단하지 않는다. 새 가입·비밀번호 변경/재설정은 기존의 8자 이상 영문·숫자 정책을 유지한다.
- 탈퇴/자격증명 삭제 시 아이디 연결도 제거하며 백업 대상에 연결 테이블을 포함한다.
- 실제 회원 자격증명과 아이디 연결은 아직 생성하지 않았다. 확보된 해시 후보는 실제 기존 로그인으로 검증되지 않았다.
- 중복 이메일 13그룹·36계정은 현재 이메일 고유성 모델로 활성화할 수 없다. 임의 병합이나 임의 이메일로 치환하지 않는다. 별도 계정 식별 설계 또는 본인 확인을 거친 이메일 정리가 필요하다.

## 이메일 조사

랭크업 관리자에는 발신 이름·발신 이메일과 가입 안내 메일 템플릿 사용 설정이 있었다. SMTP 호스트·포트·인증정보는 확인되지 않았다. Daum MX는 수신 설정일 뿐 외부 서버의 발신 권한 증거가 아니다. 기존 메일 기능을 Cloudflare에 그대로 복사했다고 보고하지 않는다.

Cloudflare 자체 Email Sending의 임의 수신자 발송은 Workers 유료 요금제 조건이므로 무료 운영 조건에서는 사용하지 않는다. 기존 발송 계정 재사용 가능 여부 또는 별도 무료 발송 서비스 연결이 남았다. 실제 메일은 발송하지 않았다.

공식 근거: [Cloudflare Email Service 요금](https://developers.cloudflare.com/email-service/platform/pricing/), [발송 시작 안내](https://developers.cloudflare.com/email-service/get-started/send-emails/).
