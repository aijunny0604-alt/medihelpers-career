# 운영 기능 전체 검수와 고객 흐름 시뮬레이션 — 2026-10-18

## 결과와 범위

회원가입, 사업자등록증, 로그인·계정복구, 공고·지원·상담, 이력서·연락처 공개, 광고·열람권 결제, 사용 횟수, 환불, 관리자 권한, 파일 접근, 이전 링크와 복구 도구를 일괄 재검수했다. 실제 카드사 승인·이니시스 취소는 실행하지 않았다. 운영 사이트에는 시험 회원·광고·주문을 생성하지 않았다.

## 발견하여 수정한 화면 오류

1. **공고 검색 초기화 후 조건 재발생:** 서울 검색 주소에서 초기화하면 5개 전체 공고가 보였지만 주소에는 서울 조건이 남았다. 새로고침 시 다시 0개로 돌아가는 것을 실제 운영 화면에서 재현했다. 초기화 시 주소의 검색 조건도 지운다.
2. **마이페이지 탭 불일치:** 결제 화면에서 문의 탭으로 이동해도 주소는 `tab=payments`여서 새로고침하면 결제 화면으로 돌아갔다. 메뉴·대시보드 바로가기 모두 선택한 탭을 주소에 반영한다.
3. **지원 처리 이력 시간 불일치:** DB의 UTC 문자열을 그대로 표시해 한국 시간보다 9시간 이르게 보였다. 접수일과 처리 이력은 기존 한국 시간 포맷터를 사용한다. 격리 브라우저에서 21:01 접수가 21:01로 표시되는 것을 확인했다.

새 고객 시뮬레이션은 운영 변수 조합과 생성된 Cloudflare Worker를 사용한다. 의료인·병원·관리자 각각 신규 가입 후 가입 쿠키를 버리고 비밀번호로 새 로그인했다. 사업자등록증을 실제 D1 업로드 코드로 저장하고 관리자 다운로드 원본 바이트를 대조했다. 가입 우회용 테스트 전환은 비활성 상태다.

동일 병원 계정이 광고 신청 → 합성 PG 승인 → 광고 공개 → 새 의료인의 지원 → 병원 문의함 수신 → 관심공고 저장 → 10명 열람권 승인 → 1명 열람·재열람 → 연락처 공개 철회 → 환불 요청 → 사유를 포함한 반려 → 재접수 → 26,100원 부분 환불 기록 → 미사용 9건 종료까지 진행했다. 사용분 2,900원, 반려 사유·처리 안내·알림, 중복 승인/환불 차단과 무관한 광고 유지도 검증했다. 금액은 격리 시나리오 예시이며 모든 고객에게 자동 적용하는 환불 정책을 의미하지 않는다.

PG 응답은 메모리에서 합성하며 그 외 외부 네트워크는 차단했다. 검사 과정에서 두 번의 시험 구성 오류(ArrayBuffer의 SQLite 변환 누락, 합성 MID 누락)를 수정했다. 제품 오류 또는 실제 운영 결제 실패로 분류하지 않는다.
