# 무료 정식 배포 설정 준비 — 2026-10-11

사용자가 랭크업 DB 접근 문제를 보류하고 다음 작업을 요청했다. 원본 자료 부족을 해결된 것으로 처리하지 않고 배포 설정을 정리했다.

- Cloudflare 빌드 기본 설정에서 R2 바인딩 두 개를 제거했다. D1 업로드를 사용하고 자동 삭제는 비활성화한다. R2 가입이나 유료 서비스 생성 없음. 무료 한도 내 운영은 트래픽·저장량에 따라 달라진다.
- `deploy/cloudflare.production.example.json`은 별도 운영 Worker/DB를 위한 템플릿이다. 기존 시험 DB ID를 복사하지 않았으며 검증한 운영 DB ID를 입력하기 전에는 사용할 수 없다. 서버·DB를 새로 만든 것은 아니다.
- 대표 주소는 `https://www.medihelpers.co.kr`. 도메인 route와 workers.dev 공개 연결이 없고 점검·읽기 전용·가입/결제 차단 상태다. 바로 배포 가능한 운영 완료 설정이 아니다.
- 기존 검수 Worker의 바인딩/설정은 변경하지 않았다. 새 Worker에는 비밀값이 자동 이전되지 않으므로 비밀 관리 도구에서 별도로 설정·검증해야 한다. 키 재발급은 하지 않는다.
- D1 백업은 기존 `scripts/backup-d1.ps1`로 별도 저장한다. D1 업로드 사용을 외부 자동 백업 완료로 설명하지 않는다.

## 전환·복귀 순서

1. 운영 DB에 검증한 이전 자료를 반영하고 회원 소유권·공개 상태·권리를 대조한다. 시험 데이터와 섞지 않는다.
2. 운영 Worker의 인증·메일·이니시스 비밀 설정과 실제 역할 접근을 확인한다. 카드 시험은 사용자가 추후 진행하기로 한 항목이며 현재 결제 차단을 유지한다.
3. 기존 주문의 지연 콜백 경로와 새 데이터의 복귀 처리를 확보한 뒤 www/apex 연결을 적용한다. 템플릿에는 이를 대신할 임의 경로를 넣지 않았다.
4. 복귀 시 Worker route/custom domain과 웹 DNS를 함께 확인하고 A121.254.171.115·DNS 전용으로 복구한다. 메일 레코드는 유지한다. DNS 복구가 신규 데이터의 랭크업 역이전을 대신하지 않는다.
