# 모바일 이전 공고 링크 보완

2026-10-11 기존 홈페이지를 iPhone User-Agent로 익명 GET하자 `/m/`으로 이동했다. 모바일 홈에 실제 공개 공고 324/296/285/135/140의 `/m/content/work_employ_detail.html?no=` 링크가 있었다. 새 Worker는 PC 경로만 명시적으로 처리하고 있어 모바일 북마크가 새 공고로 연결되지 않았다.

모바일 경로를 기존 legacyRecruitmentLink 함수에 연결했다. 원본 PC sourceUrl로 정확히 매핑된 공개·게시중·유효기간 내 공고만 새 상대경로로 301 이동한다. 권한 변경, 초안 공개, 쿼리 전달은 없다. 중복 매핑/잘못된 번호는404, POST는405다.

PC와 모바일 각각22개 검사, 두 빌드 대상에서 총88개 링크 검사를 포함해 전체19묶음1,778개 통과. 일반/Cloudflare 빌드 성공. 실제 회원 로그인이나 결제 승인을 검증한 것은 아니다.

결제 조사: 모바일 UA의 다이렉트 페이지는 PC 표준결제 returnUrl을 그대로 노출했다. 광고 등록/서비스 안내는 모바일 홈으로 이동했으며 모바일 P_NEXT_URL/P_NOTI_URL은 확보하지 못했다. 이것으로 모바일 결제가 없다고 단정하지 않는다. 주문 제출 및 결제 엔드포인트 호출은 하지 않았다.

보호 증거: medihelpers-audit-20260927/mobile-path-0~3-20261011.html 및 mobile-legacy-audit-20261011.log. 정식 DNS와 기존 랭크업은 변경하지 않았다.
