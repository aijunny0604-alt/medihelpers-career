# 회원 유형 자동 분류와 병원 광고 즉시 게시

기준일: 2026-08-09

## 회원가입·로그인

- 회원가입 화면에서 일반회원(의사·의료인) 또는 병원회원을 한 번 선택합니다.
- 서버는 `accounts.role`에 `doctor` 또는 `hospital`을 저장합니다.
- D1 스키마는 `CHECK (role IN ('doctor','hospital'))` 제약으로 다른 역할 값 저장을 차단합니다.
- 로그인 화면에서는 회원 유형을 다시 선택하지 않습니다.
- 로그인 API가 `auth_credentials`와 `accounts`를 조인해 D1에 저장된 역할을 반환하고, 클라이언트는 그 역할에 맞는 마이페이지로 자동 이동합니다.
- 따라서 다른 PC에서도 동일한 이메일·비밀번호로 로그인하면 동일한 회원 유형과 서버 저장 데이터를 사용합니다.

## 병원 광고 게시 정책

- 관리자 사전 검수·승인·반려 단계를 제거했습니다.
- 병원 광고 주문은 결제 전까지 `draft`, 결제 승인 성공 즉시 `paid` + `published`가 됩니다.
- 이니시스 키가 없는 현재 Sites 환경에서도 가상 승인 API를 실제 호출하므로 성공 문구만 보이고 게시되지 않는 상태가 남지 않습니다.
- 과거 결제 완료 후 `draft`에 남은 광고는 공개 운영 데이터나 병원 마이페이지 조회 시 자동 게시로 복구합니다.
- 관리자 콘솔의 공고 승인·반려 버튼을 제거했습니다.
- 결제 실패·취소 공고는 공개하지 않고, 환불·취소 확정 시 노출을 회수합니다.

## 화면 정리

- 홈페이지 하단의 의사·병원·안내 링크 열을 제거했습니다.
- 로고, 고객센터 연락처, 사업자·약관 하단 정보만 간결하게 유지했습니다.
- 공개 화면의 `검수`, `검수 대기` 표현을 제거하고 등록 정보 확인 또는 결제 상태 표현으로 정리했습니다.

## 유지하는 안전장치

- 회원 본인확인과 계정 정지·탈퇴 처리는 공고 검수와 무관한 계정 보안 기능이므로 유지합니다.
- 결제 금액·서명·주문 소유권·멱등성 검증은 결제 보안 기능이므로 유지합니다.
- 관리자는 신고, 정책 위반, 법적 요청에 따른 사후 숨김·삭제를 할 수 있습니다.

## 검증

- 역할 저장·로그인 자동 분류 테스트를 추가했습니다.
- 광고 주문→가상 승인→자동 게시와 과거 결제 완료 `draft` 복구 테스트를 추가했습니다.
- 관리자 승인·반려 UI와 홈페이지 하단 링크 열이 다시 생기지 않는 회귀 테스트를 추가했습니다.
- 자동 테스트 106개가 통과했습니다.
