최신 구현과 검증 범위는 [의료인 이력서 연동 검수](RESUME_INTEGRATION_AUDIT_20261018.md)를 우선한다. 2단계 작성, 본인 저장·수정, 별도 구직글 공개, 지원 당시 사본 보존을 사용한다. 관리자 메뉴는 읽기 전용이며 이력서 단독 삭제·문서 다운로드는 제공하지 않는다.

## 2026-09-15 구직글 공개 관리

## 현재 구현 상태

- `/resume`은 로그인 의료인 본인 계정의 구조화 이력서를 D1 `resumes`에 저장합니다.
- `/resume` 수정 진입 시 `GET /api/resumes`의 최신 저장본 또는 `?id=`로 선택한 본인 원본과 `detail`·프로필 사진을 불러옵니다. `?new=1`은 별도 새 이력서를 만듭니다.
- 이름·연락처·이메일·직군은 회원정보를 우선 사용합니다. 수정 가능한 전문분야·지역 등은 기존 저장본과 작성 중인 값을 보존합니다.
- 이력서 프로필 사진은 설정된 업로드 저장소의 `profiles/{accountId}/resume-profile/`에 저장합니다. 현재 운영은 D1 저장소를 사용하며 R2는 설정 시 지원합니다. 본인·관리자, 공개 이력서 열람권 병원 또는 지원본을 받은 병원만 조회합니다.
- 상담·병원 지원 시 저장된 복수 이력서 중 하나를 선택하며, 서버가 소유권을 검사하고 접수 당시 스냅샷을 D1에 보존합니다.
- 관리자 콘솔과 마이페이지가 같은 D1 데이터를 읽습니다. 다른 PC에서도 같은 계정으로 조회·수정할 수 있습니다.
- 구직글은 전용 페이지에서 별도 게시 원장에 작성하고 저장된 본인 이력서를 선택합니다. `linkedResumeId`로 같은 원본을 참조하되 게시 제목·희망 조건·연락처 공개 정책은 글 단위로 수정합니다.
- PDF·DOC·HWP 같은 일반 문서 첨부는 실제 저장·악성 파일 검사 체계가 없으므로 제공하지 않습니다.

## 과거 발견 사항과 해결

초기 구현에서는 의사 후보 정보를 받는 통로가 다음처럼 단절돼 있었습니다. 현재는 해결됐습니다.
1. **이력서 등록(`/resume`)** — 과거 localStorage 임시 저장에서 D1 소유자 저장·조회·수정으로 전환 완료.
2. **헤드헌팅 상담 파일 업로드** — 저장되지 않던 문서 첨부 UI를 제거하고 저장된 D1 이력서 선택 제출로 교체 완료.
3. **상담 텍스트** — `/api/consultations` D1 저장과 선택 이력서 스냅샷 연결 완료.

따라서 현재는 의료인이 선택한 이력서가 헤드헌팅 상담 또는 병원 직접 지원의 올바른 수신자에게 전달됩니다.

## 전략 결정 (2026-07-18 사용자 확정)

### 우리 홈 이력서 "전용"으로 간다 ✅ (외부 파일 업로드 제거)
- **우리 홈 이력서(`/resume`)만 사용.** 외부 PDF/DOC/HWP 업로드는 제거.
- 이유:
  1. **프로그램적으로 훨씬 간편** — 일반 문서 저장·검사 체계를 운영하지 않고 구조화 입력을 사용한다. 선택 프로필 사진에는 저장소·형식 검사·비공개 접근 통제가 필요하다.
  2. **데이터 100% 구조화** — 진료과·경력·희망지역이 필드로 저장 → 검색·필터·매칭·인재정보란 자동등록 가능. PDF는 검색 불가.
  3. **후보 이탈 우려 낮음** — 아빠가 큐레이션하는 헤드헌팅(대량지원 아님)이라, 진지한 이직 의사는 우리 양식 작성 부담이 크지 않음.
- **조치**: 헤드헌팅 상담 폼의 "기존 이력서 공유" 파일 업로드 UI(HeadHunterRequestPage.jsx:375~392)는 제거하고, "이력서 작성하기(`/resume`)" 링크로 대체.

## 목표 흐름

```
의료인 → [우리 이력서 작성 + 선택 프로필 사진]
        → 서버 저장 (구조화 이력서=D1 / 프로필 사진=권한형 D1/R2)
        → 아빠 관리자 콘솔에서 상세 열람
        → (동의 시) 인재정보란에 익명 등록  [[HEADHUNTING_BOARD_PLAN]]
병원 → 후보 보고 "연결 요청" → 그 의사의 이력서/파일이 케이스에 자동 첨부
```

## 구현 범위 (M단위) — 파일 업로드(R2) 제거로 단순화

1. **M1 · 이력서 서버 저장 — 완료**: `POST/GET /api/resumes`, D1 소유자 검증, 최신본 수정과 복수 새 이력서 지원.
2. **M2 · 문서 업로드 UI 제거 — 완료**: 외부 문서 대신 사이트 이력서 작성·관리·선택 제출.
3. **M3 · 관리자 열람 — 완료**: 관리자 콘솔 구조화 이력서 열람과 감사 경계.
4. **M4 · 선택 첨부 — 완료**: 상담/병원 지원 시 선택 이력서 소유권 검사와 접수 스냅샷 저장.
5. **M5 · 인재정보 연동 — 완료**: 의료인이 전용 구직글을 작성하고 원본 이력서 ID를 연결합니다. 실명·연락처는 목록 payload에 복사하지 않으며 연락처는 글 단위 `private/ticket` 정책을 적용합니다.
6. **M6 · 작성자 관리 — 완료**: 게시판·마이페이지에서 본인 글 수정·소프트 삭제, 서버 소유권 검증과 활동 이력을 제공합니다.

## 보안·법무 주의

- 이력서는 **개인정보**. 수집 목적·보유기간·동의 필수(LEGAL_PRIVACY_SIGNUP 준수).
- 회원 본인·관리자만 접근. 열람 감사 로그.
- 실명·연락처 포함 이력서는 인재정보란(익명)과 분리 저장. [[SECURITY_DATA_EXPOSURE_PLAN]]
- 일반 문서 업로드는 제공하지 않는다. 선택 프로필 사진의 저장소·접근 권한은 별도로 검수한다.

## 열린 질문

- 복수 버전 허용 완료. 기본 수정은 최신 이력서, `?new=1`은 신규 작성.
- 작성은 기본정보/경력·소개 2단계다. 공개하려면 전문분야·희망지역·30자 이상 소개 등을 별도로 검증한다.
