# AUTH

## 2026-08-30 병원 즉시 가입 정책

- 의료인과 병원 가입은 모두 제출 완료 즉시 계정과 세션을 생성합니다. 로그인 화면에서 회원 유형을 다시 고르지 않고 DB의 역할로 자동 분류합니다.
- 병원 가입은 사업자등록증 PDF/JPEG/PNG/WEBP 제출이 필수이며, 서버가 최대 10MB와 파일 서명을 검사합니다. 원본은 공개하지 않고 비공개 R2에 보관합니다.
- 사업자등록증은 가입 승인 자료가 아니라 기관 제출 이력입니다. 관리자 승인·반려·대기 상태와 그에 따른 로그인 차단은 사용하지 않습니다.
- 새 병원 계정은 즉시 `verification_status=verified`, 제출 이력은 `approved/system-auto`로 기록합니다. 기존 `unverified`, `pending`, `rejected` 병원도 최초 스키마 확인 때 같은 즉시 가입 정책으로 정규화합니다.
- 관리자 콘솔은 회원·사업자등록증 제출 이력을 읽기 전용으로 조회합니다. 병원 가입, 공고, 결제, 콘텐츠를 승인·반려하는 쓰기 기능은 없습니다.
- 계정 자체가 `suspended` 또는 `withdrawn`이면 역할과 무관하게 로그인과 보호 기능을 계속 차단합니다.

## 2026-08-30 구직글 작성 권한 확인

- `/job-seeker-posts/new`는 로그인한 의료인(`doctor`) 계정만 사용할 수 있습니다. 로그아웃 상태와 병원·관리자 계정은 등록 폼 대신 역할 안내와 뒤로가기·홈 버튼만 봅니다.
- 상단 `일반회원` 테스트 전환은 의료인 테스트 계정으로 D1 세션을 발급합니다. 전환 후 같은 페이지에서 저장 이력서 조회와 구직글 작성 흐름이 이어집니다.
- 로그인 세션이 없는 상태에서 의료인 전용 안내가 보이는 것은 권한 게이트의 정상 동작이며, 이력서 또는 구직글 API 장애로 간주하지 않습니다.

## 테스트 계정 (개발·데모용, 2026-08-02)

로그인 화면(`/login`) 하단과 데스크톱·모바일 상단 헤더에 **원클릭 테스트 버튼 3개**(일반회원·관리자·병원회원)를 둔다.
버튼은 브라우저에서 비밀번호를 전송하지 않고 서버 전용 `POST /api/auth/test-switch`를 호출한다.
서버는 아래 예약 계정만 대상으로 계정·역할·잠금 상태를 복구하고 새 D1 세션을 발급한다.

| 구분 | 이메일 | 비밀번호 |
|---|---|---|
| 관리자 | `admin@medihelpers.co.kr` | `medihelpers1234` |
| 병원 회원 | `hospital-test@medihelpers.co.kr` | `medihelpers1234` |
| 의료인 회원 | `doctor-test@medihelpers.co.kr` | `medihelpers1234` |

- ⚠️ 관리자 계정이 실제로 관리자 권한을 가지려면 배포 환경변수 `ADMIN_EMAILS`에
  `admin@medihelpers.co.kr`이 포함돼야 한다(Cloudflare `wrangler.toml`에는 기본값 포함).
- Sites 테스트 배포에서는 `ADMIN_EMAILS=hr@medihelpers.co.kr,admin@medihelpers.co.kr`로 설정해 상단 관리자 전환 버튼이 실제 관리자 콘솔로 이동한다.
- 테스트 전환용 비밀번호는 클라이언트 번들에 포함하지 않는다. 전환 API는 표의 예약 역할 외 임의 이메일·역할을 받지 않는다.
- 테스트 전환 뒤에는 새 세션 응답의 역할을 앱 공용 인증 상태에 즉시 반영하고 전체 계정 정보만 백그라운드에서 재확인한다. 현재 페이지를 다시 로드하지 않으므로 입력 중인 화면과 위치를 유지하며, 이전 계정 조회가 늦게 끝나도 요청 순번으로 무시한다. 기존 계정의 PBKDF2 비밀번호 해시는 전환 때마다 재계산하지 않는다.
- 정식 오픈 전 배포 환경변수 `TEST_ACCOUNT_SWITCH_ENABLED=false`를 설정한다. 그러면 헤더·로그인 화면의 테스트 버튼과 `POST /api/auth/test-switch` API가 함께 비활성화된다. QA 기간의 기본값은 활성화다.

> **'화면 미리보기'(QA 프리뷰) 기능은 폐지됨(2026-07-25).** 페이지 이동을 막는 문제가 있었고,
> 이제 모든 화면이 실제 로그인 세션 기준으로만 동작한다. `/qa-preview`는 홈으로 정규화된다.

## 현재 로그인 구현

### 가입 정보의 공고·이력서 자동입력

- 앱 최상위 `/api/account` 한 번의 응답에 로그인한 본인의 공통 프로필, 역할별 가입 기본값과 병원 제출 정보를 포함합니다. 하위 공고·이력서 화면은 추가 계정 조회 없이 이 상태를 사용합니다.
- 병원 공고는 가입 제출 이력에 저장된 병원명·대표자·사업자번호·주소와 회원 프로필의 담당자·연락처·이메일을 불러옵니다. 증빙 문서 원본과 R2 키는 계정 응답에서 제외합니다.
- 의료인 이력서는 이름·연락처·이메일·직군·전문분야·지역을 불러옵니다. 서버 저장도 로그인 계정의 기본값으로 누락 항목을 보완하지만 다른 계정 정보는 참조하지 않습니다.

### 쿠키·탭 토큰 충돌과 일시 오류 처리

- 정상 브라우저의 기준 세션은 HttpOnly 쿠키입니다. 같은 탭에 과거 보조 bearer 토큰이 남아 있어도 쿠키를 먼저 검증하며, 쿠키가 없거나 만료된 경우에만 보조 토큰을 이어서 확인합니다.
- 이중 토큰 중 하나가 만료·삭제됐다는 이유만으로 로그인 전체를 실패 처리하지 않습니다. 로그아웃할 때는 요청에 포함된 두 세션을 모두 폐기합니다.
- `/api/account`의 네트워크·D1 일시 오류는 로그아웃 근거가 아닙니다. 앱은 3회 짧게 재시도하고, 이미 확인된 회원 권한을 유지하면서 3초 뒤 자동 재연결합니다.
- `/api/member-center`가 일시 실패해도 공용 로그인 상태가 회원이면 재로그인을 요구하지 않습니다. 회원 데이터가 도착하기 전에는 빈 활동 수치를 표시하지 않고 로딩 화면을 유지합니다.
- 실제 `signedIn:false` 계정 응답 또는 명시적인 로그아웃 응답만 앱을 비회원 상태로 전환합니다.

- 브라우저 앱은 `/api/account`를 최상위에서 한 번 조회하고 계정·역할·프로필·이메일 상태를 하위 화면에 전달합니다. 하위 화면이 계정을 다시 요청하지 않으므로 느린 연결에서도 서로 다른 역할 판정이 경쟁하지 않습니다.
- 계정 응답 전에는 실제 로그인·가입·공고 등록 문구를 추측해 표시하지 않고 동일 크기의 중립 자리만 유지합니다. 응답 후 현재 역할에 맞는 행동만 한 번 표시합니다.
- 로컬 개발에서는 `?slow-auth=1`로 계정 응답을 500ms 늦춰 첫 렌더를 재현할 수 있으며, 원클릭 테스트 역할 전환도 운영 API와 같은 세 역할을 지원합니다.
- 테스트 역할 전환 이벤트에는 서버가 확정한 계정 역할과 관리자 여부를 함께 전달합니다. 헤더·마이페이지·권한 게이트는 이를 즉시 공유하고, 후속 `/api/account` 확인은 현재 화면을 로딩 상태로 되돌리지 않습니다.

- 메디헬퍼스 자체 이메일·비밀번호 로그인을 사용합니다. OpenAI/ChatGPT 로그인으로 이동하지 않습니다.
- 비밀번호는 사용자별 무작위 salt와 PBKDF2-SHA-256(100,000회) 해시로 D1에 저장하며 원문은 저장하지 않습니다.
- 로그인 세션은 일반 회원 7일, **관리자 12시간** 만료입니다. 기본 인증은 `HttpOnly`, `Secure`, `SameSite=Lax` 쿠키이며 D1에는 세션 토큰의 SHA-256 해시만 저장합니다.
  - 브라우저가 사이트 쿠키를 차단하는 경우 로그인 화면이 요청한 응답에 한해 탭 단위 `sessionStorage` 보조 토큰을 발급합니다. 이 토큰은 같은 출처의 `/api/` 요청에만 `Authorization: Bearer`로 전달되고, 외부 주소에는 전달하지 않습니다.
  - 보조 토큰은 해당 탭을 닫거나 로그아웃하면 삭제됩니다. 서버는 쿠키가 있으면 쿠키를 우선 사용합니다.
  - 관리자 판별은 `ADMIN_EMAILS` 기준이며, 세션 만료와 쿠키 `Max-Age`를 함께 맞춥니다. 관리자 계정이 탈취되면 전 회원 개인정보·결제 상태에 접근할 수 있어 노출 시간을 줄입니다.
  - ⚠️ `ADMIN_EMAILS`가 비어 있거나 오타가 나면 관리자도 7일 세션이 됩니다(오류 없이 조용히 완화됨). 운영 배포 전 반드시 값 확인.
- 로그인 5회 실패 시 해당 계정 로그인을 15분 잠급니다.
  - **잠금 상태는 응답 내용으로 구분되지 않습니다.** 잠긴 계정도 비밀번호 오류와 동일한 401·동일 문구를 반환하고, 잠금 여부와 무관하게 해시를 계산해 응답 시간 차이도 줄입니다(단, 완전한 상수 시간은 아님 — DB 조회 유무 등 잔여 편차는 남습니다). 예전에는 잠긴 계정에만 429를 돌려줘서 아무 비밀번호나 5번 넣어보면 가입 여부를 알 수 있었습니다(계정 열거).
  - 잠금 중에는 실패 횟수를 더 올리지 않습니다(공격자가 계속 시도해 잠금을 무한 연장하는 것을 방지).
- **역할이 바뀌면 해당 계정의 기존 세션을 전부 무효화**합니다(`DELETE FROM auth_sessions`). 의사 계정이 병원으로 전환될 때 예전 세션이 새 권한을 그대로 얻는 것을 막습니다.
- 로그인한 회원에게 데스크톱 헤더, 모바일 펼침 메뉴, 마이페이지 왼쪽 메뉴에 **로그아웃** 버튼을 제공합니다. 로그아웃은 현재 D1 세션을 폐기하고 보안 쿠키와 탭 보조 토큰을 모두 삭제한 뒤 홈으로 이동합니다.
- 기존 계정·역할·동의·프로필 데이터는 유지하고 `auth_credentials.account_id`로 자체 로그인 자격증명을 연결합니다.
- D1 테이블은 `ensureAccountSchema`가 런타임에 자동 생성하며 기존 D1 바인딩을 재생성하거나 다시 연결하지 않습니다.

### 다른 PC·브라우저 로그인

2026-08-02 Sites v230 기준으로 새 브라우저 세션에서 병원·의료인·관리자 테스트 계정 전환, 역할별 마이페이지/관리자 콘솔 이동과 로그아웃을 다시 확인했습니다. 서버 계정과 D1 세션을 사용하므로 특정 PC의 로컬 데이터에 의존하지 않습니다.

- 회원 계정과 비밀번호 해시는 브라우저 저장소가 아니라 공용 D1에 저장되므로, 가입한 이메일·비밀번호로 다른 PC에서도 로그인할 수 있습니다.
- 로그인 상태 자체가 PC 사이에 복사되는 것은 아닙니다. 새 PC나 새 브라우저에서는 같은 계정으로 한 번 더 로그인해야 하며, 성공하면 해당 환경용 독립 세션이 생성됩니다.
- 여러 PC의 정상 세션은 동시에 유지됩니다. 한 PC에서 로그아웃하면 그 PC의 현재 세션만 종료되고 다른 PC의 세션은 유지됩니다.
- 브라우저가 보안 쿠키를 저장하지 못하면 해당 탭에만 보조 토큰을 둡니다. 보조 토큰은 다른 PC·브라우저·탭으로 동기화되지 않습니다.
- 상단 테스트 역할 전환도 서버의 공용 D1 계정과 세션을 사용하므로, 로컬 저장 데이터가 없는 다른 PC에서도 동일하게 동작합니다.

### 계정 찾기·비밀번호 재설정 요청

- `/account/recovery`의 아이디 찾기는 회원가입 때 저장한 이름·휴대전화가 일치하면 **가입 이메일 주소 자체**를 해당 이메일로 안내합니다. 이 서비스의 로그인 아이디는 이메일입니다.
- 비밀번호 재설정은 가입 이메일이 일치하면 30분 동안 한 번만 사용할 수 있는 링크를 발송합니다. 링크를 사용하면 새 PBKDF2 비밀번호를 저장하고 기존 로그인 세션·남은 링크를 모두 무효화합니다.
- 요청은 `account_recovery_requests`, 재설정 링크 상태는 `account_password_resets`에 저장됩니다. 재설정 토큰 원문은 저장하지 않고 SHA-256 해시·만료·사용·발송 상태만 보관하며, 링크 URL에도 가입 이메일을 넣지 않습니다.
- 공개 응답과 화면은 계정 존재 여부, 실제 발송 대상, 내부 접수번호를 알려주지 않습니다. 같은 정보의 5분 내 재요청도 새 메일이나 토큰을 만들지 않습니다.
- 실제 발송에는 서버 환경변수 `RESEND_API_KEY`, `RESEND_FROM`이 모두 필요합니다. 누락된 환경에서는 성공 발송을 가장하지 않고 요청만 접수되었다고 안내합니다.

## 역할

- General (`doctor` 내부 키): 공개 공고 탐색, 선택형 의료인 인증, 이력서, 비공개 상담 신청
- Hospital: 병원 인증, 광고 등록, 익명 인재 탐색, 유료 소개 요청
- Headhunter: 상담, 후보 추천, 동의 확인, 면접·조건 조율
- Admin: 회원·결제·권한·게시물·개인정보 열람 기록 관리

화면에는 `의료인 회원`으로 표시하지만 기존 DB와 API 호환을 위해 내부 역할 값은 당분간 `doctor`를 유지합니다. 이 값만으로 의사 면허가 인증된 것으로 판단하지 않습니다.

- 로그인한 계정이 현재 화면에 필요한 역할과 다르면 재로그인·재가입을 요구하지 않고 현재 역할을 설명하는 안내 페이지만 표시합니다.
- 역할 불일치 상태에서는 보호된 폼을 화면 뒤에 렌더링하지 않습니다. 비회원에게만 로그인 경로와 제한된 미리보기를 제공합니다.
- 계정 API 응답 전에는 비회원 역할을 추측하지 않습니다. 헤더와 역할별 CTA는 공용 인증 상태가 확정될 때까지 고정된 중립 자리만 유지하며, 각 페이지가 계정을 다시 조회하지 않습니다.

## 인증

- 의료인: 본인 확인과 면허 또는 자격 확인
- 병원: 사업자등록 정보와 담당자 재직 확인
- 운영자: 다중 인증과 최소 권한 원칙 적용
- Google·Kakao·Naver 로그인은 인증 수단으로만 사용하며, 권한과 자격은 서버 검증 후 별도로 부여합니다.
- 같은 이메일을 가진 소셜 계정을 자동 연결하지 않고 로그인된 계정에서 재인증 후 연결합니다.

## 운영 가입 게이트

운영 환경은 이용약관 v1.0·개인정보처리방침 v1.0, `SIGNUP_ENABLED=true`, `LEGAL_DOCUMENT_STATUS=approved`, 32자 이상의 `ACCOUNT_HASH_SECRET`이 모두 준비된 경우에만 실제 서버 계정 생성을 엽니다. 현재 Sites 운영 환경은 이 조건을 충족하며, 가입 동의에는 적용 문서 버전과 시각이 저장됩니다.

- 대상 경로: `/signup`(역할 선택), `/signup/doctor`, `/signup/hospital`.
- 운영 가입은 메디헬퍼스 자체 이메일·비밀번호 인증을 사용하며 비밀번호 원문은 저장하지 않습니다.
- 필수 동의: 서비스 이용약관 v1.0, 개인정보 수집·이용 v1.0, 만 14세 이상 확인. 마케팅 수신 동의는 가입과 분리합니다.
- 계정 DB에는 인증 이메일 원문 대신 서버 비밀키로 생성한 HMAC 계정 키, 회원 유형, 동의 종류·문서 버전·시각을 저장합니다.
- 의료인 자격과 병원 담당자 권한은 가입만으로 부여하지 않고 해당 기능을 사용할 때 별도 확인합니다.

## 운영 회원가입 구현

- `/signup/doctor` 의료인 회원과 `/signup/hospital` 병원 회원의 가입 경로·목적·가입 후 이동을 분리합니다.
- 가입 성공 후 `/signup/welcome`에서 이름·회원 유형·가입 이메일과 역할별 다음 작업을 안내합니다. 화면은 서버 세션을 다시 확인하므로 URL만 직접 연 비회원에게 가입 완료 정보를 보여주지 않습니다.
- 가입자 축하 메일은 가입 이메일로, 대표자·관리자 신규 가입 알림은 `ALERT_EMAIL_TO`로 보냅니다. 두 메일은 계정·프로필·동의·세션 저장 이후 백그라운드에서 독립적으로 처리하며 실패해도 가입을 취소하지 않습니다.
- 가입 메일에는 비밀번호·해시·세션·내부 인증정보를 포함하지 않습니다. 실제 발송에는 `RESEND_API_KEY`, `RESEND_FROM`이 모두 필요하고, 미설정 상태에서는 축하 화면이 발송 완료를 가장하지 않습니다.
- 현재 Sites에서 메디헬퍼스 자체 이메일·비밀번호 인증과 D1 세션을 사용합니다.
- 가입은 `의료인 / 병원·의료기관` 역할을 먼저 고른다. 면허번호·주민등록번호·마케팅 동의는 받지 않는다. 병원은 사업자등록번호와 주소를 받는다(위 병원 회원 절 참고).
- 이메일 원문은 자체 로그인 조회용 `auth_credentials`와 회원 운영 프로필에 저장하고, 기존 도메인 데이터 연결에는 HMAC-SHA-256 계정 키를 계속 사용합니다.
- 이용약관, 만 14세 이상 확인, 개인정보 처리 안내 확인을 서로 다른 유형과 문서 버전으로 기록합니다.
- 소스에 포함된 약관·개인정보 안내 버전이 `draft`가 아니고 `SIGNUP_ENABLED=true`, `LEGAL_DOCUMENT_STATUS=approved`, 32자 이상의 `ACCOUNT_HASH_SECRET`가 모두 설정된 경우에만 서버 가입 API를 엽니다.
- Google·Kakao·Naver 외부 로그인은 인증 공급자, 각 사업자 앱 심사와 키가 확정된 뒤 동일한 가입 완료 API에 연결합니다. 자격증명 없이 성공을 흉내 내는 버튼은 제공하지 않습니다.

### 의료인 회원

- 목적: 채용공고 탐색, 관심공고, 비공개 이직 상담, 이력서·지원 관리
- 가입 후 별도 확인: 비공개 공고 열람·소개 진행 시 의료인 면허 또는 자격
- 기본 이동: 채용정보
- 회원가입 시 휴대폰 본인인증 없음(휴대폰은 연락용 일반 입력), 이메일+비밀번호 자체 로그인

### 병원 회원

- 목적: 채용공고·구직 의료인 인재 탐색, 채용 의뢰, 열람권 결제, 동의 기반 소개 요청
- 가입 후 별도 확인: 공고 등록·소개 요청 시 의료기관과 담당자 관계
- 기본 이동: 의료인 채용(채용공고 + 구직 의료인 인재 통합)
- **가입 필드(2026-07-25 정리)**: 담당자 성명·직책, 휴대폰, 이메일, 비밀번호, 병원·기관명, 대표자명, **사업자등록번호(필수·숫자 10자리)**, 병원 주소. 선택: 부서명·상세주소·홈페이지·팩스.
  - **기관 유형·병원 대표 전화·우편번호 필드는 제거**(요청).
  - **병원 주소는 다음(카카오) 우편번호 검색으로 입력**한다('주소 검색' 버튼 → **페이지 안 인라인 모달**(iframe embed) → 실주소). CSP에 `t1.daumcdn.net`·`ssl.daumcdn.net`(script)·`postcode.map.kakao.com`·`postcode.map.daum.net`(frame)을 허용해야 동작한다.
    - ⚠️ `.open()`(팝업 창)이 아니라 `.embed()`(인라인 iframe)를 쓴다. 팝업 창은 `about:blank`가 우리 CSP를 물려받아 카카오 콘텐츠가 '콘텐츠 차단'으로 막혔다(2026-07-26 수정).

## 권한 정책

- 무료 권한은 공개 공고와 익명 인재의 기본 조건, 헤드헌터 상담을 제공합니다.
- 가상 결제 완료 시 광고 노출·인재 열람권은 D1 서버 권한으로 발급됩니다. 운영 실결제 권한 발급은 이니시스 MID·서명키·웹훅 검증과 Cloudflare 이전 후 같은 서버 원장에 연결합니다.
- 병원 후보 문의는 의료인의 연락처 구매가 아니라 헤드헌터 확인과 후보자 동의를 거치는 소개 요청입니다.

- 민감정보 열람, 다운로드, 소개, 권한 변경은 모두 감사 로그에 기록합니다.

## 보안 헤더 (HTML 응답)

HTML 응답에 다음 헤더를 붙입니다. 생성 위치는 `scripts/package-sites.mjs`의 HTML 응답부입니다.

| 헤더 | 값 | 목적 |
|---|---|---|
| `Content-Security-Policy` | 아래 참고 | XSS·리소스 주입 차단 |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | HTTPS 강제 |
| `X-Content-Type-Options` | `nosniff` | MIME 스니핑 차단 |
| `X-Frame-Options` | `DENY` | 클릭재킹 차단 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 외부로 경로 유출 방지 |
| `Permissions-Policy` | 위치·마이크·카메라·payment 차단 | 불필요한 권한 차단 |

### ⚠️ CSP가 막을 수 있는 외부 리소스 (회귀 주의)

CSP는 허용 목록에 없는 외부 리소스를 **조용히** 차단한다. 서버 로그·자동 테스트에는 흔적이 남지 않고
브라우저 콘솔에만 기록되므로, **배포본을 실제 브라우저로 열어봐야** 발견된다.

현재 반드시 유지해야 하는 허용 항목:

| 리소스 | 지시어 | 빼면 생기는 일 |
|---|---|---|
| `https://fonts.googleapis.com` | `style-src` | **사이트 전체가 대체 글꼴로 렌더**(2026-07-22 실제 발생) |
| `https://fonts.gstatic.com` | `font-src` | 위와 동일(폰트 파일 자체가 차단) |
| `https://stdpay.inicis.com`<br>`https://stgstdpay.inicis.com` | `script-src`·`connect-src`·`frame-src`·`form-action` | 결제창이 뜨지 않음 |
| `https://t1.daumcdn.net`<br>`https://ssl.daumcdn.net` | `script-src` | 병원 가입 주소 검색 스크립트 로드 실패 |
| `https://postcode.map.kakao.com`<br>`https://postcode.map.daum.net` | `frame-src` | 주소 검색 인라인 iframe이 '콘텐츠 차단' 화면으로 표시됨 |

이니시스 결제창의 경우 사용자에게는 스크립트 로드 실패 안내가 표시되지만(`src/inicisPay.js`),
글꼴 차단은 아무 안내 없이 화면만 바뀌므로 더 늦게 발견된다. CSP를 조이는 작업을 할 때 위 표를 반드시 확인할 것.
