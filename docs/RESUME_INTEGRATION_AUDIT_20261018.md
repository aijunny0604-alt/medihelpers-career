# 2026-10-18 의료인 이력서 연동 검수

## 범위와 상태

의료인 등록·수정 → 마이페이지 → 구직글 연결·공개 철회 → 병원 열람권 → 직접 지원 제출본 → 관리자 기록을 검수했다. 운영 고객 데이터는 수정하지 않고 합성 계정을 사용하는 격리 Worker/D1에서 저장·결제 승인 모의응답·환불·비공개 변경을 검사했다. 실제 카드 거래는 수행하지 않았다.

현재 이 문서의 변경은 배포 후보이며 배포 결과는 아래에 확정 기록한다. 기존 랭크업, 회원 이전 보류, 카드 결제·관리자 수동 환불 방식은 유지한다.

## 검증한 관계

- 회원정보의 이름·전화·이메일·직군을 서버 기준으로 사용한다. 개인정보 필드는 일반 회원이 이력서 저장으로 변조할 수 없다.
- 이력서 저장만으로 공개되지 않는다. 게시에는 본인 이력서 선택 및 게시 동의가 필요하다.
- 이력서 수정은 연결된 구직글의 상세 경력에 반영되지만, 이미 제출한 상담·직접 지원의 내용과 사진은 당시 사본으로 보존된다.
- 관리자 콘솔과 마이페이지에서 같은 저장본의 최신 제목과 내용을 확인한다.
- 사진은 익명·미열람 병원에게 차단되고 본인·관리자에게 허용된다. 병원은 공개 중인 동일 이력서의 열람권 또는 자신이 받은 지원 사본의 사진만 볼 수 있다.
- 이력서에 연결된 여러 글을 조회해도 동일 후보에 대해 이용권을 중복 차감하지 않는다. 비공개 연락처는 구매 후에도 미공개다.
- 미사용분 환불 보류·부분 환불·기존 열람권 정책은 전체 회귀 검사로 확인했다. 이번에 유효기간이나 환불 정책을 변경하지 않았다.
- 소유자가 아닌 계정의 이력서 ID 조회·수정은 거절된다. 관리자 개인 작성 화면과 관리자 전체 기록 조회는 분리되어 있다.

## 검증 결과

- 수정 전 생성 Worker에서 누락 ID/타인 ID 조회, 20개 밖의 선택 이력서, 다른 공개 글에 연결된 사진 권한 등 4개 회귀 실패를 재현했다.
- 수정 후 전체 25개 묶음 **2,945 검사 통과**. 기존 2,900에서 45개 추가. 단위 544, 새 계정 통합 흐름 119 포함. 합계에 별도 재실행을 중복 계산하지 않았다.
- 의료인·병원·관리자 모두 격리 DB에서 새 가입 후 로그아웃하고 비밀번호로 다시 로그인해 권한을 검증했다.
- 배포 전 운영 D1 전체 백업 4,978,814바이트를 격리 SQLite에 복원하여 51개 테이블·integrity ok·외래키 오류 0 확인. 기존 Worker와 운영 바인딩 30개 동일.
- Sites/Cloudflare 두 빌드, 생성 서버 구문 검사, git diff --check 통과.
- 브라우저: 강제 조회 실패에서 폼 차단 → 재시도로 원본 복구 → 사진 선택·저장 완료 → 관리자에서 같은 사진과 최신 경력 조회. 마이페이지의 구직글 편집 연결 및 없는 글의 안전한 오류 화면 확인.
- 비공개 검증 자료는 저장소 밖 medihelpers-audit-20260927/resume-*에 보관한다. 합성 화면 캡처만 사용하며 운영 회원 자료·비밀번호·키를 Git에 포함하지 않는다.

## 운영 시 알아둘 범위

관리자는 `/admin/console`의 **이력서 기록**에서 전체 내용과 사진을 읽는다. 이 메뉴는 타인의 원본을 수정·삭제하는 도구가 아니다. 의료인 본인은 `/mypage?tab=resume`에서 수정·구직글 비공개/재공개/삭제를 관리한다. 구직글 삭제는 연결 이력서 자체를 삭제하지 않는다.

현재 본인 이력서 목록은 최근 20개, 구직글 목록은 최근 50개다. 선택한 옛 이력서와 연결된 구직글의 편집 조회는 목록 범위 밖이어도 지원한다. 원본 이력서 단독 삭제·대량 관리·PDF/HWP 첨부 기능은 제공하지 않는다. 프로필 사진만 업로드할 수 있다.

실제 카드 승인·취소 성공과 외부 고객이 사용하는 모든 기기의 동작을 보장하는 검사가 아니다. 운영 URL·새 관리자 인증·배포 자산 확인은 별도 기록한다.
