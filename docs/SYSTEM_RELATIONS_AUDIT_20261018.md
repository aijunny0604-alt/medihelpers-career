이 문서는 단일 화면의 표시 여부가 아닌 업무 흐름의 저장·권한·노출·회수를 검증한다. 결제/가입 직전 검수는 [별도 기록](PAYMENT_SIGNUP_AUDIT_20261018.md)이며, 아래 결과와 중복 합산하지 않는다. 현재 수정본은 배포 전 후보이며 실제 배포 결과는 마지막 절에 갱신한다.

## 이번에 재현하고 수정한 오류

1. **의료인 공고 지원 불가:** 의료인 채용 상세는 직접 지원 화면으로 연결됐지만 접수 API가 `doctor_job`만 허용해 `medical_job`에서 409가 발생했다. 두 종류 모두 등록 병원에 제출본·동의 기록·알림을 전달하도록 수정했다.
2. **공개범위/수신자 상태 불일치:** 공고 ID로 직접 접수하면 관리자 전용·병원 전용 공고 또는 정지된 병원에도 제출할 수 있었다. 현재 공개범위, 모집 상태, 광고 만료와 수신 병원 활성 상태를 확인한다. 헤드헌팅 공고를 직접 지원으로 바꾸는 요청도 차단한다.
3. **헤드헌팅 공고 검증 누락:** 존재하지 않거나 숨김·마감·만료된 공고 문의가 저장되고 URL로 조작한 제목·병원명이 그대로 보존됐다. 실제 공고 원장과 게시 채널을 확인하고 제목·병원명을 서버 원본에서 가져온다.
4. **상담과 채용 관리 기록의 부분 저장:** 채용 건 생성 실패를 무시하고 상담 성공을 반환했다. 상담·동의·활동·알림·채용 건을 하나의 DB 트랜잭션으로 저장한다. 실패 시 전부 취소되고 재시도에서 한 번만 생기는지 확인했다.
5. **관리자 무한 로딩:** 운영 브라우저에서 로딩이 지속됐으며 기존 코드에 요청 제한 시간이 없었다. 관리자 데이터 전송과 JSON 읽기에 20초 제한을 두고 연결 지연 안내·재시도를 제공한다. 로그인 오류 외에는 자동으로 네 번 재요청하지 않는다. 운영 API의 별도 직접 조회는 200이었으므로 브라우저 지연의 근본 원인을 서버 장애로 단정하지 않는다.

## 정상 작동과 구분할 운영 제약

- **기존 이전회원 282명:** 사용자 지시대로 보류. 신규 가입과 별개다.
- **실결제:** 요청 경로는 개방돼 있지만 실제 카드사 승인·취소·정산까지 입증한 상태는 아니다.
- **환불:** 운영자가 이니시스에서 전액 취소 후 검증된 금액/TID/시각을 새 관리자 원장에 반영하는 방식이다. 자동 INIAPI 취소는 꺼져 있다.
- **상담·CRM:** 접수·자동 채용 건 생성·조회는 연결됐다. 현재 관리자 상태 변경/후보 추가/면접 관리 API는 조회 전용이며, 구 컴포넌트의 편집 코드는 운영 경로에서 사용되지 않는다. 담당 배정·대화형 메시지까지 구현 완료로 표시하지 않는다.
- **문자/메일:** 사이트 알림함과 외부 발송은 별개다. 외부 키·발신자·수신자 미설정은 `not_configured`, 실패는 `failed`로 남긴다. 이번 운영 메일·SMS 도달 시험은 하지 않았다.
- **백업:** R2 자동 파일/DB 백업을 설정 완료로 간주하지 않는다. 이번 운영 D1 SQL export와 메모리 복원 무결성을 확인했으며 기존 랭크업 전체 파일 백업/FTP는 사용자 보류다.
