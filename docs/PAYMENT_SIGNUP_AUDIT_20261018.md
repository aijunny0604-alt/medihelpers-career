## 범위와 실제 거래 구분

www.medihelpers.co.kr 정식 서비스의 가입, 광고 결제, 환불 반영과 접근 제한을 점검했다. 실운영 DB에는 가짜 회원·광고·주문을 만들지 않았다. 기존 이전회원 282명은 보류 상태를 유지하며 랭크업 호스팅·원본·기존 응답 전달 경로는 보존한다.

**실제 카드 승인·이니시스 취소는 수행하지 않았다.** 승인 응답 시험은 격리 SQLite에서 PG 응답을 합성했다. 별도의 실제 Cloudflare D1에서는 가입·이미지 저장·비밀번호 로그인·권한·PC/모바일 서명 주문 생성까지만 검증했다. 운영 SDK 로드 성공은 카드사 승인 성공을 의미하지 않는다.

## 수정한 운영 오류

1. 고객 화면의 환불 요청은 금액 0(금액 미확정)으로 생성되는데 관리자 수동 취소 반영은 원 주문 금액과 같아야 한다고 검사하여 정상 요청도 실패했다. 원 주문의 유일한 승인 거래, TID, 전액 취소 금액, 시각·증빙을 검증한 후 금액 확정·원장 기록·권리 회수·광고 비노출을 한 트랜잭션으로 처리한다. 부분 금액은 허용하지 않는다.
2. PC 결제창을 닫으면 제출 잠금이 풀리지 않았다. 공식 SDK의 닫기 처리 후 같은 주문 복구 화면을 표시한다. 승인 시도 전 본인 미결제 주문만 원 금액으로 다시 연다. 이미 승인 요청이 있는 주문은 이중 승인을 막기 위해 대사로 넘긴다. 상품 가격·세금·공고 상태·인재 공개 범위가 변경된 주문도 재검증한다.
3. 사업자등록증을 잘못된 파일로 교체하면 이전 파일이 남을 수 있었다. 잘못된 선택은 첨부 상태를 비우고 오류를 표시한다. 삭제 후 동일 파일 재선택도 가능하다. 빈 파일을 미리 거부하고 가입 저장 중에는 중복 제출을 막는다.
4. 사업자등록번호의 문자 포함 입력을 숫자만 추출하여 받아들이던 동작을 수정했다. 화면·서버가 동일 함수로 숫자 10자리와 하이픈·공백만 허용하고 구체적인 오류를 안내한다. 저장은 하이픈 없는 10자리다. **국세청 등록·휴폐업 조회나 사업자 본인 확인 기능은 아니다.**
5. Content-Length 유무와 관계없이 가입 multipart 요청은 12MiB, 개별 서류는 10MiB로 제한한다. 중복 payload, 비객체 JSON을 거부한다. PG form 응답도 64KiB와 중복 필드 제한을 적용한다.
6. 미사용 vinext 의존성을 제거하고 source-map-js 취약 버전을 갱신했다. npm audit 전체 의존성 결과 알려진 취약점 0건. 이것은 모든 보안 위험이 없다는 보증은 아니다.
