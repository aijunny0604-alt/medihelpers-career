## 이번 수정

1. **병원 수신 상세의 이력서 누락:** 직접 지원은 DB에 저장돼도 마이페이지가 메시지만 렌더했다. 제출 당시 이력서·지원 연락처·사진을 수신 상세에 연결했다. 서버가 허용한 수신 자료만 사용하며 최신 개인 이력서를 다시 조회하지 않는다.
2. **사진 권한 범위:** 열람권 하나가 같은 작성자의 관련 없는 다른 사진까지 허용하던 조건을 해당 이력서 사진으로 제한했다. 직접 지원을 받은 병원에는 해당 제출본 사진만 허용한다.
3. **만료 공고:** Worker 생성 문자열의 정규식 이스케이프 소실로 서버 만료 필터가 작동하지 않았다. 한국 날짜 기준으로 목록·직접 지원·마이페이지 표시를 맞추고 종료 공고 제출은 409로 거부한다. 브라우저 시간대와 서버 간 만료 기준도 통일했다.
4. **기존 DB 초기화:** 동의 테이블이 없는 구형 DB를 정상으로 판정하던 스키마 확인을 보완했다. 기존 레코드를 유지하면서 0013 동의 테이블이 생성된다.
5. **비밀번호 재설정:** 마이그레이션 생성 DB에 없는 `password_changed_at` 열 때문에 발생한 500을 수정했다. 해당 열이 있는 과거 런타임 DB도 지원한다. 동일 토큰의 동시 제출은 한 번만 성공하고 기존 세션을 폐기한다. 열을 무조건 추가하는 ALTER 마이그레이션은 사용하지 않는다.
6. **회원정보 부분 저장:** 알림만 PATCH했을 때 이름·전화가 지워지거나 생략한 알림 설정이 초기화되지 않도록 기존값과 합친다. 서버 저장 실패를 UI 성공으로 간주하지 않는다.
7. **동의 값과 역할 전환:** 문자열 `"true"` 등 비정상 알림값은 400으로 거부한다. 다른 계정의 선택 마케팅 상태가 전환 후 남지 않도록 기본값을 초기화한다. 연락처 공개 철회도 증빙에 남긴다. 레거시 가입 API도 최신 안내 버전을 확인한다.
8. **탈퇴·파일 정리:** 가입 추가정보를 삭제하고 거래 보존 계정의 광고를 종료한다. 미참조 개인 사진과 만료된 사업자 증빙 파일을 정리한다. 활성 계정의 업로드 초안은 7일 보존하고 이미 제출한 지원서의 사진은 연결 기록이 남아 있는 동안 유지한다. 불명확한 만료일은 임의 삭제하지 않는다. 실패는 기록 후 다음 보존 실행에서 재시도한다.
9. **업로드:** 선언 MIME과 PNG/JPEG/WEBP/GIF 파일 시작 바이트를 검사한다. 전체 이미지 디코딩이나 악성 파일 검사까지 구현한 것은 아니다.
10. **생성 코드의 문자열 문제:** 문자 수신·발신 번호의 숫자 정규화와 구형 주문 스키마의 열람권 상품 분류 정규식 이스케이프를 수정했다.
11. **화면 연결:** 병원 계정에 직접 지원 버튼이 잘못 표시되던 상단 조건, 병원명을 채용 진료과로 자동입력하던 매핑, 병원 등록 공고를 관리자 등록으로 설명하던 문구, 베이직 양식 번호를 수정했다.
12. **목록 캐시·로딩:** 역할 변경 때 이전 공개범위의 목록 캐시를 비우고 새 응답을 받는다. 오래된 요청이 새 역할 응답을 덮지 않도록 처리한다. 공고/인재 상세 직접 진입 시 로딩 전 404를 표시하지 않고, 조회 실패에는 다시 불러오기를 제공한다. 알림 읽기 실패도 성공으로 표시하지 않는다.

이전 대기분의 관리자 KST 날짜·체크섬·다운로드 무결성, 실제 DB COUNT, 서비스별 동의·철회 사본, 선택 가입정보 분리도 포함한다. 세부 내용은 [9월 12일 변경 기록](PRIVACY_ADMIN_UPDATE_2026-09-12.md).

## 실운영 전에 남은 범위

- Sites는 가상 결제다. 실제 PG 승인·취소·웹훅·정산은 승인된 운영 환경에서 별도 시험해야 한다.
- 실 이메일·문자 공급자 계약/발신 승인·키·전달 결과, 병원 확인/파기 담당 등 운영 절차가 필요하다.
- 개인정보 수탁자·국외 보관 관계, 방침 개정 공지/시행과 기존 회원 안내, 열람권 연락처 제공 방식은 사실 확인과 법률 검토가 남아 있다. 보호책임자는 사용자 확인값을 보존했다. 동의 UI/DB 구현이 법률 검토 완료를 뜻하지 않는다.
- 요청 기반 하루 첫 백업은 고정 시각 실행 보장이 없다. 39개 DB 테이블 JSON 복원은 합성 SQLite에서 시험했으며 운영 D1 복원, R2 이미지·서류 파일 자체 복제/복원은 미검증이다.
- 조회 전용 관리자는 기록·백업을 확인할 수 있지만 상태 변경·환불 실행·파기 운영을 화면에서 처리하지 않는다. 현재 사용자가 유지한 정책을 임의로 바꾸지 않았다.
- 실제 동시 사용자 부하, 장시간 운영, 다양한 실제 단말/보조기술, 대량 이력서·파일 정리 한도는 이번 격리 시험 범위 밖이다. 빌드 JS 청크 약 705KB(압축 약 198KB)는 성능 개선 후보다.
