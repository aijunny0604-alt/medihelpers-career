# 운영 전환 실행서

작성일: 2026-09-24 · 상태: 준비용 초안, 실행 승인 전. 빈칸과 미완료 항목은 통과로 간주하지 않는다.

## 확정한 방향과 확인한 증거

- 기존 랭크업 호스팅·DB·첨부·관리자 접근은 유지한다. 해지·삭제·기존 PG 키 교체는 이번 작업에 포함하지 않는다.
- 대표 도메인은 기존 medihelpers.co.kr을 이어 쓴다. www/apex 최종 대표 주소와 실제 연결 레코드는 DNS 전체 내역 확인 후 확정한다.
- 사용자 제공 이니시스 계약 화면에서 MID `UPmedihelp`, 홈페이지 `medihelpers.co.kr`, 사용 상태, 계약일 2017-10-19를 확인했다. 직접 관리자 접속 검증이나 신규 환경에서의 MID 재사용 승인은 아직 아니다.
- 부가정보 화면의 면세 표시·자동 매입·현금영수증 사용·월1회 정산은 현재 PG 화면 설정이다. 새 상품의 세무 처리나 수수료·새 모듈 사용 권한까지 확정한 증거는 아니다. 상품별 금액/과세 설정을 담당자에게 확인한다.
- 신규 사이트는 테스트 공개본 377. 운영 Cloudflare 환경, 실회원 이전, 실결제·실환불·메일 수신은 미검증이다.

## 실행 전 필수 통과 조건

담당자는 역할로 표시했다. 실제 담당자·증거 위치·검증일을 채워야 한다. 비밀키와 회원 원본은 문서/Git에 넣지 않는다.

| 항목 | 담당 | 현재 | 통과 증거 |
|---|---|---|---|
| 랭크업 전체 DB/파일 백업·원본 건수 확보 | 기존 운영자 | 미완료 | 보호 저장 위치, 추출시각, 해시, 용량 |
| 전체 회원·권리 대사, 중복/누락 예외 처리 | 개발+운영 | 미완료 | [검수표](MIGRATION_ACCEPTANCE.md) 승인본 |
| 비밀번호 호환 또는 본인확인 재설정 경로 | 개발 | 미완료 | 정상/정지/이메일 누락 회원 시험 |
| 이니시스 기존 MID·모듈·취소 이용 조건 확인 | 운영+PG | 미완료 | 문의 답변 또는 계약 근거 |
| PC/모바일 승인·취소·중복·장애 후 대사 | 개발+운영 | 미완료 | 주문/TID별 결과, 민감정보 제외 |
| 양쪽 쓰기 중지·신규 결제 중지·증분 추출 | 개발+기존 운영자 | 미구현/미검증 | 실제 API 차단 및 진행 중 결제 처리 시험 |
| 신규 변경분의 랭크업 복구 경로 | 개발 | 미구현 | 격리 환경 역이전 시험 또는 보류 처리 승인 |
| D1/R2 백업 복원 리허설 | 개발 | 미완료 | 복원 후 건수·파일·로그인 검증 |
| 운영 DNS 전체 내역·HTTPS·메일 유지 | DNS 담당 | 미완료 | 변경 전후 레코드표, 실제 송수신 |
| 예시/테스트 계정·권한 제거 | 개발+운영 | 미완료 | 테스트 전환 불가, 실제 목록/권리 검수 |
| 구 URL 연결·모바일·권한별 최종 검수 | 개발 | 미완료 | 대표 사용자 흐름 및 301 매핑 |
| 고객 안내·담당자·복구 판단 시간 확정 | 운영 책임자 | 미완료 | 안내 승인본, 비상 연락 체계 |

`SIGNUP_ENABLED=false`는 전체 쓰기 중지가 아니다. `PAYMENT_LIVE=true`는 실결제 모드이며 결제 중지 장치가 아니다. 현재 사전검증 도구는 importer/역이전 도구가 아니다. 위 기능은 구현·시험 전까지 차단 항목으로 유지한다.

## DNS 변경표 — 실행 당일 실측해서 채우기

| 대상 | 변경 전 실제 값/TTL/프록시 | 변경 후 승인 값 | 복구 값 | 검증자 |
|---|---|---|---|---|
| apex A/AAAA/CNAME | 미기입 | 미기입 | 미기입 | 미기입 |
| www A/AAAA/CNAME | 미기입 | 미기입 | 미기입 | 미기입 |
| NS·DNSSEC/DS·CAA | 미기입 | 변경 필요 여부 확인 | 미기입 | 미기입 |
| MX·SPF·DKIM·DMARC·기타 서브도메인 | 전체 export 필요 | 기존 기능 보존 | 미기입 | 미기입 |

9월 24일 www A=121.254.171.115, TTL=600은 참고 스냅샷이다. 현재 전체 zone이나 복구용 확정값으로 대신하지 않는다. DNS 제공자 변경이 필요하면 기존 zone 복제와 DNSSEC 절차를 별도 시험한다. TTL만으로 전환/복구 완료 시간을 보장하지 않는다.

## 당일 실행 순서

| 순서 | 실행 | 다음 단계 진입 조건 |
|---|---|---|
| 1 | 담당자·작업창·후보 SHA·백업 위치·복구 판단시각 기록 | 모든 필수 검수 승인 |
| 2 | 기존 사이트 가입/수정/삭제/신규 주문 중지, 새 사이트도 쓰기 닫기 | UI뿐 아니라 API 차단 확인 |
| 3 | 진행 중 주문 목록 확보, PG 승인/입금/취소 통보는 안전하게 수신·대사 | 승인 여부 미상 주문의 담당/처리 계획 확보 |
| 4 | 동결 시각 T0 기록, 마지막 DB+파일 증분 추출·해시 기록 | 최종 원본과 백업 복원 가능 |
| 5 | 신규 운영 DB에 멱등 이전, 전체 대사 | 누락/중복/고아·금액차이 0, 승인 예외 명시 |
| 6 | 쓰기 닫힌 상태로 HTTPS·권한·첨부·메일·구 URL 검증 | 새 환경 검수 완료 |
| 7 | 운영 책임자가 Go/No-Go 기록 후 승인된 웹 DNS 변경 | 이전 레코드와 복구 절차 보관 |
| 8 | 외부 네트워크별 새/구 응답과 인증서 확인 | 캐시로 구 사이트에 접근해도 쓰기 차단 유지 |
| 9 | 준비된 점검 계정으로 핵심 흐름 검증 후 신규 쓰기 개방 | 시각 T1 기록, 변경분 추적 시작 |
| 10 | 첫 실제 주문·권리 부여·PG 대사 확인, 1시간/당일/다음 영업일 점검 | 불일치 없고 지원 담당 대기 |

단계별 소요 시간은 리허설에서 측정한다. 검증 실패 상태에서 예정 오픈 시간에 맞추려고 다음 단계로 넘기지 않는다. 기존 사이트 검증용 접속은 인증된 임시 경로나 올바른 TLS를 유지한 제한된 접근으로 준비하고, 공개 복제 사이트를 만들지 않는다.

## 중단 조건과 기록

개인정보 무단 노출, 소유권 뒤바뀜, 중복 청구, 금액 불일치, 권리 중복 지급이 한 건이라도 확인되면 신규 쓰기/주문을 즉시 중지하고 [복구 실행서](ROLLBACK_RUNBOOK.md)를 따른다. 결제 승인 상태 미상은 재결제를 유도하지 않고 PG 조회·원장 대사로 해결한다.

운영 수치 기준 초안: 핵심 로그인/게시/주문 경로 연속 3회 실패 또는 5분간 서버 오류율 1% 초과 시 신규 개방을 중단한다. 최소 표본·관측 도구·복구 판단 제한 시간은 리허설 후 운영 책임자가 확정한다. 관측 불가도 개방 승인 근거가 될 수 없다.

실행 기록 양식: 실행번호 / 시작·완료시각(KST와 UTC) / 담당 / 소스 SHA / 데이터 기준시각 / 증거 위치 / 결과 / 예외 / 승인자. 실제 운영 자료는 접근 제한된 운영 저장소에 보관한다.
