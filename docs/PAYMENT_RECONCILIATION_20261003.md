# 결제 조회·이전 재점검 — 2026-10-03

## 후속: Workers 실제 통신에서 발견한 오류 수정

공식 [INIAPI TLS 시험 매뉴얼](https://manual.inicis.com/download/TLS12_test_manual.pdf)의 공개 테스트 자격정보와 이미 취소된 시험 거래만 사용해 Cloudflare 원격 미리보기에서 직접 확인했다. 운영 MID·키·거래는 사용하지 않았다.

- 기존 `redirect:'error'`는 Workers에서 지원하지 않아 요청 전 TypeError가 발생했다. PC 승인/망취소/환불, 모바일 승인/망취소 및 거래조회가 사용하는 세 통신 함수에서 `manual`로 변경했다. 기존 `response.ok` 검증으로 3xx를 거부하며 다른 주소로 키나 요청을 전달하지 않는다.
- 변경 후 시험 서버 거래조회 HTTP200 / SUCCESS / CANCEL, 공식 기취소 시험 HTTP200 / 500626을 받았다. 실제 신규 카드 승인·환불 성공을 뜻하지 않는다.
- 매뉴얼의 127.0.0.1은 공개 시험에만 사용했다. 운영 Workers clientIp의 올바른 값이나 HOSTrankup 계약의 외부 호스팅 지원은 이 결과로 확정하지 않는다.
- 단위371 + 생성 Worker PG86 = 457개 통과. HTTP301/302/303/307/308에 대해 세 함수 모두 응답 본문을 읽지 않고 한 번의 요청 후 거부하는 15개 회귀검사를 추가했다. build 통과. 기존 627개 전체 재실행으로 표현하지 않는다.
- 임시 원격 시험 서버는 종료했다. 근거는 Git 밖 `vendor-test-result-20261003.json`; 원문 구매자·카드 정보는 보관/출력하지 않았다.

또한 Workers TLS 소켓 연결 자체는 성공했으나 localAddress는 제공되지 않았다. 검수 D1을 새로 내보내 로컬 복원을 검사했다: 45개 테이블, integrity 정상, 외래키 오류 0, 보호 반입 직후와 행 해시 차이 0. 이는 랭크업 전체 DB/첨부 복원 완료를 의미하지 않는다. 실제 DB 복원·키 재발급·정식 도메인 전환은 수행하지 않았다. 업체 문의는 사용자 응답에 따라 미발송으로 유지한다.

## 이번 보완

관리자 환불 요청 화면에 ‘이니시스 거래 조회’를 추가했다. `/api/admin-payment-inquiry`는 관리자·동일 출처 POST만 허용하고, 서버에 저장된 해당 주문의 확정 승인 한 건에서 TID를 선택한다. 사용자 전달 TID는 사용하지 않는다.

[공식 거래조회 V2 규격](https://manual.inicis.com/pay/etc-inquiry.html)에 따라 환경별 고정 URL, 서버 키 서명, 15초 제한, 리다이렉트 거부를 사용한다. MID/TID/주문번호/금액/카드 지불수단을 비교한다. 부분 취소·미확인 응답·통신 실패는 대사 필요로 남기며 카드/구매자 정보와 원문 오류는 반환하지 않는다.

조회는 주문·원장·이용 권한을 바꾸지 않는다. 조회 성공은 실제 승인/환불 또는 권리 회수 완료를 뜻하지 않는다. 원거래 TID가 없는 불명확한 승인 건은 가맹점 관리자 확인이 필요하다. 검수본의 쓰기 차단도 유지한다.

## 실제 관리자 확인

- 기존 MID의 2026-01-23 카드 승인 1건·100,000원에 대해 정확한 TID·주문번호·승인 시각·상품명과 취소일 없음 상태를 확인했다.
- 상점그룹은 `HOSTrankup`이다. 새 호스팅 이용 가능 여부를 확인한 것은 아니다.
- 2026-09-27~2026-10-03 카드 통합승인내역은 0건. 이 결과로 결제 정상 동작을 보장하지 않는다.
- 랭크업 보관 자료에는 주문번호/TID 정확 일치가 없고 날짜·금액 후보만 1건이다. 임의 연결하거나 기존 거래를 취소하지 않았다.
- 상세 근거는 Git 밖 보호 폴더의 `inicis-verified-transaction-20261003-private.json`과 `pg-archive-match-20261003-private.json`에 저장했다. PG 키 재발급·금전 거래 없음.
