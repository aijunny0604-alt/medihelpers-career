## 원인 → 수정

- **[P2] 홈페이지가 일반 글자로 표시됨:** 기존 공고의 `payload.website`는 비어 있고 홈페이지가 `description`에만 있다. 본문을 일반 `<p>`로 표시하여 URL·이메일·연락처가 클릭되지 않았다. 안전한 http/https·mailto·tel 링크를 만드는 공통 표시기를 추가했다. 별도 홈페이지 항목이 비어 있으면 본문 항목에서 보완한다.
- **[P2] 빈 줄과 항목 배치가 불규칙함:** 예전 표를 텍스트로 옮기면서 탭·반복 빈 줄·사진 캡션이 남았다. 병원·기관 정보 / 모집·근무조건 / 자격요건 / 접수·문의의 항목과 값으로 분리하고 PC 2열, 작은 화면 1열로 배치했다.
- **[P3] 같은 긴 본문을 두 번 노출:** 병원 정보와 포지션 설명에서 같은 summary를 반복했다. 전체 본문은 포지션 영역에 한 번 표시하고 병원 정보에는 사진과 기관 항목을 배치했다. 원본 본문이 있는 공고에 중복 생성되던 일반 설명도 제외했다.

## 내용 보존 원칙

- 저장된 공고·운영 DB·기존 원문은 수정하지 않는다. 화면 표시만 정리한다.
- 빈 담당업무, 숫자가 없는 `모집인원 명`은 `공고에 미기재`로 표시하고 값을 추정하지 않는다.
- 표 사이의 자유 문단, 급여·경력·연차 등 원문은 그대로 유지한다. 서로 다른 원문 급여 표현도 임의로 통일하지 않는다.
- 구조가 확인된 이전 공고의 단독 `전경 사진`, `내부` 등의 잔여 캡션만 제거한다. 사진과 홍보 이미지는 기존대로 유지한다.
- 기존 기관정보 값이 있으면 본문 추출값보다 우선한다. 서버가 잠근 공고 본문에서는 추가 기관정보를 추출하지 않는다.
- 홈페이지는 새 창으로 열며 `noopener noreferrer`를 적용한다. 임의 HTML은 실행하지 않고 위험한 URL 스킴이나 자격증명이 포함된 URL은 링크로 만들지 않는다.
- 전화·이메일 링크 대상 속성은 검증했으며 실제 전화나 이메일 발송을 실행하지 않았다. 외부 병원 홈페이지의 정상 운영까지 보장하는 작업은 아니다.
