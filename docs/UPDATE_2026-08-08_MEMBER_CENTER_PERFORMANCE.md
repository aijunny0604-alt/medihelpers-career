# 회원정보 로딩 성능 개선 (2026-08-08)

## 원인

- `/api/member-center` 요청마다 이미 생성된 D1 테이블과 인덱스의 `CREATE` 문을 반복 실행했습니다.
- 프로필, 알림설정, 활동, 상담, 결제, 이력서, 메시지 조회를 순서대로 기다려 DB 왕복 시간이 누적됐습니다.

## 개선

- 대표 테이블을 가볍게 확인하고 같은 Worker 인스턴스에서는 스키마 준비 결과를 재사용합니다.
- 새 환경이나 최신 테이블이 없는 경우에만 기존 자동 스키마 생성 로직을 실행합니다.
- 프로필·알림·상담·결제·메시지 등 회원 데이터 조회를 하나의 D1 `batch` 요청으로 묶어 원격 왕복 횟수와 응답 편차를 줄입니다.
- 알림 개수 전용 API는 기존처럼 필요한 알림 데이터만 반환합니다.

## 보존 사항

- 로그인·권한 검사와 계정 소유권 조건은 변경하지 않습니다.
- 기존 D1/R2 바인딩과 `.openai/hosting.json`은 변경하지 않습니다.
