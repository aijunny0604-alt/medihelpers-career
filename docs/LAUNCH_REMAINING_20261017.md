# 출시 준비의 남은 실행 조건

## 이번에 이어서 처리한 범위

관리자 인수 검수 결과를 출시 실행표에 반영하고, 사용자 공개 화면의 운영 상태 안내를 점검했다. 실제 service-status는 mode=open, checkoutEnabled=false였다. 광고 화면에는 결제 즉시 게시만 안내되고 회원가입 폼은 signupEnabled=false 안내가 없어 사용자가 신청 가능하다고 오해할 수 있었다.

광고 페이지는 서버 상태를 한 번 조회해 결제 중단/확인 중/조회 실패를 명시한다. 정상 운영 시 안내와 현재 상태를 구분하며 실패를 정상 결제로 간주하지 않는다. 폴링·저장·PG 호출은 없다. 회원가입은 서버의 가입 차단 상태를 사용해 개인정보 입력 전에 안내한다. 기존 로그인·가입·결제 권한과 서버 차단 로직은 변경하지 않는다. 개발용 데모는 그대로 유지한다.

검증: 단위473개, 운영 샘플 제외/로컬 데모 보존8개, 일반/Cloudflare 빌드 및 Worker 문법·diff 검사 통과. 이전 전체1,860검사의 재실행이 아니다. 이번 변경은 표시 안내이며 새 3역할 로그인 시험을 수행한 것은 아니다.

## 실행할 수 없는 항목과 조건

| 항목 | 남은 조건 | 현재 처리 |
|---|---|---|
| 회원 사용재개 | 사용자가 보류를 해제하고 이용 재개 기준 결정 | 기존282계정 보류 유지 |
| 신규 결제 개방 | 사용자의 실제 카드 승인·취소 시험 및 원장/권리 대사 | 결제 차단 유지, 수동 환불 절차 준비 |
| 구 주문의 전환 시 처리 | 구 신규 주문 중단 시점과 미완료 거래 정리 또는 검증된 콜백 유지 결정 | 임의로 구 결제 설정 변경하지 않음 |
| 정식 도메인 전환 | 위 전환 범위 확정, 최종 DNS/DB 백업 후 전환 지시 | 기존 서버 유지 |
| 구 전체 파일 백업 | FTP 재개 결정과 유효 접속정보 | 사용자 보류 유지 |
| R2 자동 백업 | 무료-only 방침과 별도로 저장소 이용 결정 필요 | 신청하지 않음. 기존 CLI D1 백업과 구분 |

이미 완료한 HTTP/이미지/DB 비교를 계속 반복하는 것으로 이 조건들을 충족했다고 보고하지 않는다. 새 증거·코드 변경·전환 시점에 필요한 검사만 다시 수행한다. 정식 출시 완료나 법률 검토 완료로 표시하지 않는다.
