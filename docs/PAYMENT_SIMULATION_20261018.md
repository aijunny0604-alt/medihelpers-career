# 결제 코드 및 운영 설정 시뮬레이션 — 2026-10-18

## 판정

결제 코드의 PC/모바일 카드 요청 → 서버 승인 확인 → 주문 원장 → 광고·열람권 지급과 수동 환불 반영 경로가 격리 시뮬레이션을 통과했다. 실제 결제 승인·취소나 PG와의 통신 성공을 대신 증명하는 결과는 아니다.

추가 검수에서 iOS의 Chrome·네이버·카카오톡 등에서 앱카드 인증 후 원래 브라우저로 돌아오는 `app_scheme` 옵션이 빠져 있는 것을 확인했다. 공식 안내의 허용된 브라우저 식별값만 적용하도록 보완했다. Safari/Android 기본 동작과 기존 금액 서명·반환 상태·보안 옵션은 유지한다. 실제 휴대폰의 카드 앱 전환은 별도 실기기 시험 대상이다.

## 이번 시뮬레이션

- 최신 소스의 일반 빌드와 Cloudflare 빌드를 다시 생성했다.
- 기존 결제 관련 런타임 5묶음 **482검사** 재통과: 이니시스86, 광고 주문74, 열람권100, 수동 환불160, 경합/변조62.
- 새 `runtime-payment-live-config-audit.mjs`: **494검사** 통과. 실제 Cloudflare 배포용 Worker와 `cloudflare.live-with-legacy-replies.json`의 변수 조합을 사용하고, DB는 메모리 SQLite, PG 키·계정은 합성값으로 대체했다. 운영 DB 바인딩은 사용하지 않는다. 모든 외부 fetch를 가로채며 알 수 없는 외부 주소도 네트워크로 보내지 않는다.
- 정상 시나리오 **20개**: 아래 5상품 × PC/모바일 × 운영 IDC fc/ks. 동시 반환 3건·반복 반환에서도 외부 승인 호출과 지급은 주문당 한 번이다.
- 장애 시나리오 **8개**: PC/모바일 각각 승인 거절, 승인액 불일치, 승인 후 저장 실패, 승인/망취소 통신 불명. 미승인 상태에 권한을 부여하지 않고, 불명확한 거래를 다시 승인하지 않는다.
- 위 검사와 모바일 복귀 단위검사2개를 포함해 전체 **23묶음 2,685검사**, 두 빌드 통과. 482/494는 전체 결과에 포함되므로 합산하지 않는다.

## 코드와 공식 규격 대조

- PC `signature`, `verification`, `mKey`, `use_chkfake=Y`, IDC별 승인 URL과 승인 후 MID/주문/금액/수단 대조: [이니시스 PC 일반결제](https://manual.inicis.com/pay/stdpay_pc.html).
- 모바일 `P_CHKFAKE`, `P_RESERVED`, `P_NOTI`, HTTPS `P_NEXT_URL`, IDC별 `P_REQ_URL`과 앱 복귀 옵션: [이니시스 모바일 일반결제](https://manual.inicis.com/pay/stdpay_m.html).
- 승인 저장 실패는 보상용 망취소 경로를 사용한다. 일반 고객 환불과 망취소는 구분한다. 불명확한 결과는 `review`로 보존해 중복 청구를 막는다.
- 사용자/운영자 환불 흐름은 [환불 운영 절차](REFUND_LIFECYCLE_20261018.md)와 같으며, 실제 PG 취소는 관리자에서 먼저 처리하고 홈페이지에 근거를 기록한다.

## 운영에 관한 제한

- 현재 카드 결제만 지원한다. 계좌이체·가상계좌를 구현 완료로 안내하지 않는다.
- 운영 환경의 키 등록 여부와 결제 모듈 설치 여부는 실제 PG가 해당 키·상점·카드 거래를 수락한다는 증거가 아니다.
- 자동 INIAPI 환불은 비활성이다. 수동 환불 승인·반려·부분 환불 기록과 권한 반영을 검증했다.
- 기존 랭크업·회원 이전 보류·원본 주문·운영 키·DNS는 변경하지 않는다. 새 시뮬레이션은 운영 주문이나 회원을 생성하지 않는다.
