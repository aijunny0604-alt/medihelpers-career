# 홈페이지 운영 준비 검수 — 2026-09-11

## 판정

내부 시연·가상 결제 테스트는 계속 가능하지만 정식 운영 개시 판정은 보류합니다. 테스트 로그인과 관리자 권한은 사용자 요청대로 유지했습니다. 현재 공개 사이트의 테스트 관리자 전환으로 운영 정보를 조회할 수 있으므로 실제 고객 개인정보를 수집하는 환경으로 사용하기에는 부적합합니다.

## 이번 수정

- 팩으로 발급된 열람권의 주문 참조를 실제 주문 ID로 저장. 정기 정리는 기존 풀 ID 참조도 인정하여 정상 열람권을 보존합니다.
- 없는 인재·삭제된 구직글·비공개 이력서는 상세 제공 가능 여부를 먼저 확인하여 크레딧을 차감하지 않습니다. 유효하지 않은 대상의 열람권 주문도 거절합니다.
- 대상을 지정하지 않은 1명 상품은 1크레딧으로 지급합니다.
- 일일 한도 검사를 차감 앞으로 옮기고 SQLite 날짜와 ISO 날짜의 비교를 정규화했습니다. 제한 응답은 열람 성공으로 표시하지 않습니다.
- 활성 구직글을 열람한 병원이 연결 이력서의 사진을 볼 수 있도록 권한 연결을 수정했습니다. 글 삭제 후에는 해당 연결로 사진을 볼 수 없습니다. 연락처 비공개 설정은 유지됩니다.
- 신규 DB에서 누락된 가입 프로필·병원 공고/후보 테이블을 초기화하여 마이페이지 500과 상담 접수 503을 수정했습니다. 열람 이력 API도 스키마 보정을 거칩니다.
- 정적 공고·인재에 예시 표시를 추가했습니다. 예시 공고의 직접 지원과 예시/없는 인재의 상세 구매 버튼을 제거했습니다. 기존 테스트 데이터 자체는 삭제하지 않았습니다.
- 의료인 마이페이지의 폐지된 멤버십 문구를 활동 내역으로 정리했습니다.

## 검증 근거

- 자동 테스트 227개 및 프로덕션 빌드 확인. 빌드의 대용량 JS 경고는 남으며 로딩 성능 개선 여지가 있습니다.
- `npm run test:runtime`: 생성된 실제 Worker + SQL 마이그레이션 + 메모리 SQLite. 36개 명시적 검증 통과. 새 세션의 의료인/병원/관리자 전환, 비회원/역할별 API 상태, 이력서 저장·구직글 등록·중복 방지·삭제, 비공개 연락처 보호, 팩 결제/재승인/재열람, 과거 풀 참조 보존, 없는 대상 차감 방지, 일일 한도 차감 방지, 단건 적립, 병원 광고 승인·중복 방지, 상담 접수 및 실제 등록 공고 직접 지원→병원 마이페이지 전달을 확인했습니다.
- 기존 UI에서 등록한 메인·베이직 공고의 추가 검증 13개 통과: 금액, 재승인, 배너 업로드 바이트 보존, 파일 제한, 템플릿/업로드/삭제 저장과 재조회, 공고 원장과 주문 이미지 연동, 빈 제목/다른 역할 수정 거절.
- 직접 브라우저: 공개 공고 검색 0건·초기화·내과 필터, 수정본의 예시 표시와 지원/구매 차단, 관심공고 저장과 새로고침 유지, 병원 마이페이지·내 공고·390px 모바일에서 템플릿 선택→저장 완료 확인. 수정 화면의 가로 넘침 없음.
- 운영 Worker 최근 60분 오류 로그 조회 결과 0건. 이 결과는 장기간 안정성이나 부하 검증을 대체하지 않습니다.
- 실제 고객 정보나 실결제를 사용하지 않았습니다. 변경을 수반하는 접수·결제 검증은 격리된 로컬 DB에서 수행했습니다.

## 정식 운영 전에 남은 사항

1. 테스트 계정/관리자 접근 정책 전환. 현재는 유지 요청에 따라 변경하지 않았습니다.
2. 실제 PG 결제 성공·실패·취소·환불·중복 콜백 검증. 현재 Sites 가상 결제 결과로 실결제 준비 완료라고 할 수 없습니다.
3. 관리자 콘솔은 현재 조회 전용이며 환불 요청 실행은 405입니다. 담당자 배정·상담 상태 변경·환불 처리의 운영 경로를 확정해야 합니다.
4. 정적 예시와 기존 DB 테스트 공고를 실모집 자료로 교체하고 모집 마감일·광고 노출기간을 확인해야 합니다. 예시 표시는 오인을 줄이는 조치이며 실운영 데이터 전환 완료를 뜻하지 않습니다.
5. 실제 이메일·문자 도착, 본 도메인, 약관/운영절차 확정, 백업 복원 리허설과 다수 동시 사용자 부하 검증은 이번에 완료하지 않았습니다.
6. 과거에 이미 삭제되거나 잘못 차감된 열람권은 이번 수정으로 자동 복구되지 않습니다. 실제 결제 도입 전 주문·열람 이력 대조가 필요합니다.

검수는 재현한 기능과 경로에 대한 결과이며 모든 결함이 없다는 보증이 아닙니다.
