# 새 사이트 직접 클릭·화면 검수

기준일: **2026-10-20**. 시작 소스는 `f9dbe3139d6e744abcc38ffae53faa5e158cdc57`이며 GitHub 개발 브랜치와 Sites 미러가 일치했다. **기존 랭크업, 정식 도메인, DNS, 운영 DB·PG 설정은 변경하지 않았다. 새 사이트 공개 배포도 하지 않았다.**

앞선 [전체 기능 점검](NEW_SITE_FULL_AUDIT_20261020.md)의 미완료 화면 검수를 이어서 진행했다. 당시 브라우저 탭은 `data:` 오류 문서였으며, 이번에는 준비된 로컬 HTTP 검수 서버를 새 탭으로 열어 정상 접근했다. 브라우저 보호 설정을 변경하거나 차단 페이지를 우회하지 않았다.

## 직접 수행한 흐름

## 결제 검수 범위와 남은 제한

[이니시스 공식 개발 문서](https://manual.inicis.com/inipaypro/)의 공개 테스트 상점 `INIpayTest`를 사용했다. 로컬 검수 실행기에만 `--pg-window-test` 옵션을 추가했다. 합성 구매자 정보와 임시 주문을 사용하며 서버의 외부 fetch는 차단되어 있다.

운영 코드는 HTTPS 요구와 승인·금액·서명·소유권 검증을 그대로 유지한다. 로컬 실행기만 결제창의 return/close 주소를 루프백 HTTP로 매핑했다. 운영 환경 설정이나 운영 서명 키를 바꾼 것이 아니다.

결제창에서 **닫기 → 결제 취소 확인**을 눌렀으나, 외부 PG 화면에서 루프백 주소로 복귀하는 단계는 브라우저의 로컬 네트워크 보호에 차단됐다. 보호 기능을 해제하지 않았다. 따라서 다음은 완료로 표시하지 않는다.

- 실제 HTTPS 환경의 결제창 취소 후 복귀 및 같은 주문 결제창 재개
- 실제 카드 승인, 환불, 승인 후 공고 게시의 브라우저 전체 경로
- 실제 iOS/Android 앱카드 전환과 복귀

주문·승인·재개·환불·게시 로직은 아래 격리 합성 런타임 검사로 확인했으며, 실제 PG 승인 검증과 구분한다. 카드정보 입력, PG 약관 동의, 실결제·실환불은 수행하지 않았다.
