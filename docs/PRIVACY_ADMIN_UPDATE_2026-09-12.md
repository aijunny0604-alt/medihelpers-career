# 개인정보 동의·관리자 보완 — 2026-09-12

## 적용 상태

공개 배포는 353이며 이번 수정은 Git 소스와 격리 미리보기에서 검증했다. 운영 배포·운영 DB 마이그레이션은 아직 실행하지 않았다. 운영자·개인정보 보호책임자 정보(이형석, hr@medihelpers.co.kr, 051-342-5463)는 사용자가 확인했으며 변경하지 않았다. 테스트 로그인·관리자 전환 및 관리자 조회 전용 정책을 유지했다.

## 변경

- 관리자 백업의 객체 날짜를 ISO 문자열로 정규화한다. 한국 시간 표기, 로딩·실패 구분, 목록 메타데이터 요청 및 다음 페이지 조회를 추가했다. 내려받기 전 브라우저에서 SHA-256을 계산해 응답 체크섬과 다르면 다운로드를 중단한다.
- DB 현황은 별도 COUNT 집계로 표시한다. 상담 필터, 주문 수로 거래 수 대체, 계정 수로 프로필 수 대체 문제를 제거했다.
- 가입의 처리방침 확인과 필수 약관 동의를 구분했다. 선택 회원정보는 별도 선택 동의가 있어야 저장되며 해당 정보를 비우면 동의하지 않아도 가입할 수 있다.
- 상담·이력서·공고 결제·구직글에 목적·항목·보유기간·거부 안내를 표시한다. 동의가 필요한 수집과 계약 이행에 필요한 처리 안내를 구분했다.
- 병원 직접 지원은 수집·이용 동의와 제공 동의를 분리하고 실제 공고의 병원명과 제출된 병원명이 일치하는지 서버에서 다시 확인한다.
- 구직글 연락처 공개는 기본 비공개를 유지하며 별도 선택 동의가 필요하다. 기존 연락처 공개 기록을 소급 변경하지 않았다.
- 이메일 마케팅은 선택이며 문자·카카오 광고 동의를 포함하지 않는다. 설정 변경 시 동의·철회 기록을 저장한다. 발송 연동을 새로 켜지 않았다.
- 제출 기록과 동의 증빙을 같은 DB 배치로 저장한다. 동의 저장 실패 시 제출도 취소된다. 증빙은 안내문 사본, 버전, 시각, 계정·대상 식별번호와 제공 병원을 포함한다. 관리자에 최근 100건 조회 화면을 추가했다.
- `0013_processing_consent_events.sql` 추가. 백업 대상은 39개 테이블이다. 탈퇴 시 동의 이벤트를 제거하며 연결 기록 삭제 후 일일 정리에서도 남은 증빙을 정리한다. 과거 동의를 소급 생성하지 않는다.

## 검증

- 자동 테스트 229개 통과.
- 생성 Worker 기본 검수 36개, 예외 검수 58개 통과. 기존 정상 요청에 현재 안내를 확인한 입력을 명시해 계약 변경을 반영했다.
- 관리자·저장·동의 시험 63개 통과. 미동의·문자열 true·구버전 안내 거부, 선택 정보 없는 가입 성공, 선택 동의 가입 성공, 제출과 동의 기록의 동시 취소, 병원명 변조 차단, 이메일 동의·철회, 실제 DB 집계, 백업 손상·재시도 및 별도 SQLite 복원을 포함한다.
- 직접 브라우저에서 백업 한국 시각·체크섬 표시, 관리자 제공 동의 사본 조회, 지원서 미동의 차단 → 수집 동의만 선택 시 차단 → 병원 제공 동의 후 접수 성공을 확인했다. 시험용 계정·DB만 사용했다.
- 빌드 성공. 실제 D1 복원·R2 업로드 파일 복원·실PG·운영 규모 부하를 완료했다는 의미는 아니다.

## 법률·운영 확인이 남은 사항

코드 보완은 법률 검토 완료나 적법성 보증을 뜻하지 않는다. 아래 사실을 확인한 뒤 정식 운영 문구·시행일을 확정해야 한다.

1. 실제 계약상 수탁자, 재위탁 관계, 개인정보 보관 국가, 국외 이전의 근거·고지 사항. 공급사·국가를 임의로 확정하지 않았다.
2. 열람권을 사용하는 병원 회원에 대한 연락처 공개 방식에서 제공받는 자를 특정하는 방법과 동의 문구의 충분성. 개별 병원 제공 동의는 직접 지원 경로에서 구현했다.
3. 상담 종료·파기 담당과 절차, 병원에 전달된 지원서의 파기·철회 요청 처리, 이미 다운받은 사본 관리. 관리자 조회만으로 수신 병원의 삭제를 보장할 수 없다.
4. 방침 개정 공지 및 시행 시점, 기존 회원 안내, 의료 커리어 사업의 실제 계약·보존 근거. 기존 방침이 약속한 사전 안내 기간도 확인해야 한다.
5. 실제 별도 D1·업로드 파일 복구 리허설. DB JSON 백업이 첨부 파일 자체의 백업을 대신하지 않는다.
