# 기존 공고 링크 전환 준비

기존 공고의 `/work/employ_detail.html?no=324` 형식은 새 Worker에서 대응 경로가 없어 404가 됐다. 기존 검색 결과·즐겨찾기를 유지하기 위한 경로 처리를 배포 후보에 추가했다.

## 연결 조건

- 기존 `migration.sourceUrl`과 정확하게 일치하는 공개 승인 공고 한 건만 `/jobs/admin-<새 공고 ID>`로 301 이동한다.
- 의사 채용 기능이 꺼져 있거나 초안·숨김·회원 전용·관리자 전용·노출 만료이면 404를 유지한다. 같은 원본에 여러 공고가 연결돼 있어도 임의 선택하지 않는다.
- 번호 누락·중복·잘못된 형식은 거부한다. GET/HEAD만 허용하고 POST는 405로 끝낸다. 기존 결제 콜백을 이 처리로 전달하지 않는다.
- 목적지는 같은 사이트의 상대 경로이며 입력 쿼리는 전달하지 않는다. 응답은 no-store이고 원본 개인정보를 포함하지 않는다.
- DB 조회만 수행한다. 회원 활성화·공고 공개·유료 권리 생성은 수행하지 않는다.

10월5일 백업의 공고127건 모두 해당 원본 주소 형식이며 중복 원본 주소0건이다. 현재127건은 관리자 초안이므로 새 처리로도 공개되지 않는다. 실제 공개 승인을 마친 뒤에만 연결된다.

## 검증과 제한

생성 Worker+격리 SQLite에서22개 검사 통과. `npm run audit:precutover`에 포함해13묶음1,268개 검사와 build 통과. Cloudflare용 build도 통과했다. 실제 카드 결제·환불이나 운영 회원 로그인을 수행한 결과는 아니다.

이번 범위는 위 의사 공고 상세 주소다. 구 회원·구직·게시판·첨부·관리자 URL 전체 매핑, 구 결제 지연 콜백 분기까지 완성한 것으로 보지 않는다. 특히 PG 콜백은 일반 페이지301로 대체하면 안 되며 거래 출처별 별도 검증이 필요하다.

작업 전 GitHub 기준과 Sites 미러 `98d9d1c520afe9c6637667fb73b00544e92eed82` 일치 확인. 앱 배포 소스82b1201, Worker2b96835c-1d77-4eb9-942f-c6d19aed3286 유지. 앞선 로그인 수정 후보의 실제 운영 역할 검수가 남아 있어 이번 후보도 미배포다. DNS·기존 랭크업·PG 설정 변경 없음.
