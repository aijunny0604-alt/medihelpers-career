# Cloudflare 원격 환불 기록 검증 — 2026-10-09

기준 소스 `3c0694a`. 실제 검수 서비스와 분리된 임시 D1 `medihelpers-refund-proof-20261009` 및 Wrangler remote preview에서 수행했다. 운영/고객 정보와 이니시스 키는 연결하지 않았다. 시험 진입점에는 임시 토큰 검사를 적용했다.

실제 `server/manualInicisRefund.js`를 import하고 현재 서버 생성 소스의 열람권 회수 SQL을 그대로 추출해 사용했다. 저장소 SQL migrations와 런타임 관리자 스키마를 임시 D1에 적용했다. 이는 생성 Worker 전체의 인증 흐름 시험이 아니라 실제 환불 helper와 D1 트랜잭션의 원격 시험이다. HTTP 권한 검수는 별도 로컬 59개 검사 범위다.

원격 D1에서 실제 SQL 제약 오류를 발생시켰으며, 원장·환불 요청·사용 크레딧·이미 발급된 열람권·처리 claim·광고 상태가 모두 원복되는 것을 조회로 확인했다. 단순 메모리 대역 시험이 아니다. PG 네트워크 호출은 시험 코드에 없으며 돈은 이동하지 않았다.

초기 Python 기본 User-Agent는 edge에서 1010으로 거부됐다. Mozilla User-Agent로 재요청한 뒤 시험 스키마에 런타임 관리자 테이블이 빠진 오류가 나타났다. 앱이 사용하는 관리자 스키마를 동일하게 적용한 후 6개 시나리오를 처음부터 모두 통과했다. 초기 오류를 실제 결제 장애나 앱 기능 검증 통과로 취급하지 않는다.

## 배포 준비 변경

`deploy/cloudflare.staging.jsonc`와 생성 Cloudflare 설정에 `INICIS_REFUND_MODE=manual`, `INICIS_REFUNDS_ENABLED=false`를 명시했다. 검수 읽기 전용, 회원가입·결제 차단은 유지한다. 설정 검사를 추가하여 로컬 전체 **18묶음 1,574개** 및 일반/Cloudflare 빌드를 통과했다. 기존 1,573개에 설정 검사 1개를 더한 수이며, 원격 67개와는 별도 집계다.

이는 저장소의 다음 배포 설정이다. 실제 Cloudflare 운영 변수, D1 바인딩, PG 키, 정식 DNS를 변경하지 않았다. 현재 검수 Worker `2b96835c-1d77-4eb9-942f-c6d19aed3286`가 그대로임을 deployments 조회로 재확인했다.
