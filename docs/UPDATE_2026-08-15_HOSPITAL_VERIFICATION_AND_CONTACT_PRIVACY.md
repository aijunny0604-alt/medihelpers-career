# 병원 가입·의료인 연락처 보호 정책

최신 기준일: 2026-08-30
최초 도입일: 2026-08-15

## 의료인 연락처 공개 원칙

- 의료인은 이력서·구직글을 등록할 때 연락처를 `비공개` 또는 `열람권 보유 병원에 공개`로 직접 선택합니다.
- 기본값은 `비공개`입니다.
- `비공개`를 선택하면 병원이 이력서 열람권을 구매해도 성명·전화번호·이메일을 받을 수 없습니다. 열람권은 경력과 상세 이력 확인 권한일 뿐 연락처 공개 동의를 대신하지 않습니다.
- 구직 목록과 상세 화면에 빨간색 `전화번호 비공개` 안내를 표시합니다. 결제 전과 열람권 사용 후 화면 모두 전화번호·이메일이 공개되지 않음을 명시합니다.
- 연락처 공개 여부는 서버의 `GET /api/talent-detail/:id` 응답에서 최종 판정합니다. 화면에서만 가리는 방식이 아니며, 공개 목록과 중첩 상세 JSON에도 연락처 사본을 넣지 않습니다.
- 본인과 관리자는 운영·권리행사를 위해 원본을 확인할 수 있습니다. 병원에는 의료인이 선택한 범위만 제공합니다.

## 병원 회원가입 흐름

1. 병원 담당자가 병원명, 대표자명, 사업자등록번호, 주소와 사업자등록증 PDF·이미지를 제출합니다.
2. 서버는 PDF/JPEG/PNG/WEBP 형식, 파일 서명과 10MB 제한을 검사합니다.
3. 서류 원본은 비공개 R2 바인딩에 저장하고 D1에는 제출 이력·파일 키·크기·SHA-256 등 최소 메타데이터만 기록합니다.
4. 계정과 로그인 세션은 제출 완료 즉시 생성합니다. 관리자 승인·반려·대기 절차는 없습니다.
5. 신규 계정은 `verification_status=verified`, 제출 이력은 `approved/system-auto`로 기록합니다. 이 값은 자동 처리 이력이며 수동 승인을 뜻하지 않습니다.
6. 과거 `unverified`, `pending`, `rejected` 병원 계정과 제출 이력은 최초 서버 스키마 확인 때 즉시 가입 정책으로 정규화합니다.
7. 관리자 콘솔은 회원과 사업자등록증 제출 이력을 읽기 전용으로 확인합니다. 승인·반려 버튼과 관련 API 쓰기 작업은 제공하지 않습니다.

공고·결제·일반 콘텐츠 역시 사전 승인 방식으로 운영하지 않습니다. 다만 계정이 `suspended` 또는 `withdrawn` 상태이면 역할과 무관하게 로그인을 차단합니다.

## 보관·접근 기준

- 사업자등록증 원본 URL과 저장 키는 공개 응답 및 일반 회원 계정 응답에 포함하지 않습니다.
- 현재 구현 보관 기준은 제출일부터 3년이며, 관계 법령이나 확정된 내부 파기 정책이 더 짧은 기간을 요구하면 그 기준을 우선합니다.
- 탈퇴·보관기간 만료 시 원본 삭제와 D1 메타데이터 파기 작업을 운영 절차로 연결해야 합니다.
- 문서 조회·다운로드는 관리자 감사 로그와 이상 접근 알림에 연결하는 것을 권장합니다.

## 사기 가입 방지 권장안

수동 승인으로 가입 자체를 막는 대신, 위험도에 따라 별도 사후 확인을 조합할 수 있습니다.

- 사업자 상태 조회와 상호·대표자·주소 일치 검사
- 병원 공식 대표번호 콜백 또는 기관 도메인 이메일 확인
- 첫 광고 결제나 대량 열람권 사용 전 추가 확인
- 병원 담당자 변경, 이상 로그인, 장기 미사용 계정에 대한 재확인
- 허위 서류·도용 신고 시 계정 `suspended` 처리와 감사 이력 보존

## 검증 기준

- 병원 가입 응답이 계정과 세션을 즉시 반환하는지 확인합니다.
- 기존 대기·반려 병원 데이터가 자동 정규화되는지 확인합니다.
- 관리자 콘솔의 비-GET 요청이 HTTP 405로 차단되는지 확인합니다.
- 비공개 구직글의 빨간 안내와 공개 API의 연락처 원문 부재를 확인합니다.
- `.openai/hosting.json`의 Sites project_id, D1 및 R2 바인딩은 변경하지 않습니다.
