## 현재 구조 — 2026-10-18

정식 `www.medihelpers.co.kr`는 Cloudflare Workers Routes → `medihelpers-staging` Worker → production D1에 연결된다. Worker 이름은 검수용처럼 보이지만 실제 운영 DB다. Sites는 소스 미러이며 런타임을 배포하지 않는다.

- React/Vite SPA, 자체 history/popstate 라우터, lazy 화면 분리.
- `scripts/package-sites.mjs`가 공유 API 소스에서 Sites/Cloudflare 두 산출물을 만든다. Cloudflare는 정적 자산 ASSETS를 사용한다.
- 운영 콘텐츠는 D1 원장과 반입한 이미지에서 제공한다. 정적 샘플·역할 전환은 개발 전용이며 공개 배포에서 비활성이다.
- 사업자등록증·프로필 등 신규 파일은 제한된 D1 객체/청크 저장소를 사용한다. 개별10MiB·전체100MiB/5,000개 제한. 사업자등록증은 관리자 권한으로만 읽는다.
- Resend 계정 복구 메일이 연결돼 있다. 상담 알림은 별도 발신자/수신자 설정이 필요하며 SMS는 설정 여부를 구분한다.
- 실제 이니시스 서명 요청은 개방, 환불은 PG 관리자 수동 취소 후 새 원장 증빙 반영. 실제 카드 승인·취소 검증과 동일하지 않다.
- 상담/CRM은 접수와 자동 기록 생성·조회까지 연결. 관리자 상태 편집과 후보 관리의 운영 경로는 현재 조회 전용이다.
- 백업은 비공개 D1 export/복원 검증을 사용했다. R2 자동 백업이 운영 중이라고 가정하지 않는다.

각 업무 연결과 검증 경계는 [시스템 연동 검수](SYSTEM_RELATIONS_AUDIT_20261018.md)를 우선한다. 기존 랭크업 파일·호스팅을 보존하며 복귀는 [실행서](ROLLBACK_RUNBOOK.md)를 따른다.

## 권한 경계

- 인증: 메디헬퍼스 자체 이메일·비밀번호(PBKDF2-SHA256) + D1 세션 쿠키. OpenAI 로그인은 사용하지 않음
- 클라이언트 인증 상태: App 최상위 `/api/account` 1회 조회를 단일 원천으로 사용하며, 역할별 하위 화면과 프로필 자동입력 훅은 이 상태를 전달받음
- 계정 식별자: 이메일 원문을 직접 키로 쓰지 않고 `ACCOUNT_HASH_SECRET` 기반 HMAC 키 사용
- 관리자: `ADMIN_EMAILS` 허용목록을 서버에서 검사
- 역할: 내부 값 `doctor`는 일반/의료인 회원 화면, `hospital`은 병원 회원 화면에 대응
- 상태 변경 요청: 동일 출처 검사와 서버 역할 검사
- 직접 지원: 제출본 이력서를 `consultation_requests.payload_json.resumeSnapshot`으로 보존하고 공고 등록 병원에만 전달한다. 마이페이지에서 해당 제출본·연락처를 표시한다. 현재 이력서/다른 병원의 자료를 다시 조회하지 않는다.
- 사진: 본인·관리자, 해당 이력서 열람권을 가진 병원, 해당 제출 사진을 받은 병원으로 제한한다. 같은 소유자의 다른 사진은 허용하지 않는다.
- 목록 캐시: 역할 변경 시 초기화하고 늦은 이전 요청이 새 응답을 덮지 않게 한다. 상세는 로딩/연결 실패/실제 없음 상태를 구분한다.
- 공개 콘텐츠: `public`, `doctor`, `hospital`, `admin` 공개범위를 서버에서 필터링

## 주요 도메인

- 계정·동의·회원 프로필
- 상담 접수와 운영 알림
- 의사 초빙공고·의료인 채용공고·익명 인재 콘텐츠
- 헤드헌팅 채용 건과 후보 동의·면접·성공보수
- 광고·열람권 주문, 거래 이벤트, 환불 요청, 증빙(의사 멤버십은 폐지)
- 관리자 설정·카테고리·기능 플래그·감사 로그

## 비기능 기준

- 결제 승인과 민감정보 공개는 클라이언트 상태로 확정하지 않습니다.
- 깨진 레거시 JSON 한 건이 전체 관리 화면을 중단하지 않도록 안전하게 파싱합니다.
- 상태 변경과 민감정보 열람은 감사 로그 대상으로 관리합니다.
- `prefers-reduced-motion`과 기기 성능 감지를 통해 장식 애니메이션을 자동 축소합니다.
- 공개 목록의 정렬은 광고 등급을 지키되 진료과·지역 균형 노출을 적용합니다.

## 운영 데이터 보호와 남은 범위

- 개인정보·결제·인재 상세는 서버 권한 응답으로만 공개한다.
- 병원 직접 지원은 본인 이력서 스냅샷, 수신 병원 동의, 공고 공개범위와 병원 활성 상태를 확인한다.
- 병원 상담과 CRM 생성은 같은 DB 트랜잭션으로 저장한다.
- 기존 이전회원282명의 이용 재개는 사용자 보류다. 신규 가입 개방과 구분한다.
- D1 보존 정리와 별도 백업의 완료 상태를 구분한다. R2 미설정에서 자동 백업 완료를 표시하지 않는다.
- 현재 복귀 절차는 서버·Route 복귀와 신규 데이터 변경분 보존을 포함하지만 전체 양방향 역이전을 실증한 것은 아니다.
