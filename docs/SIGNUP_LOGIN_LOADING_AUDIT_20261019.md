# 가입·아이디 로그인·채용정보 조회 검수

기준: 2026-10-19. 시작 소스 `1e9712be651d2e28a40b2b56da08ea7e5498bbd1`, GitHub `agent/medihelpers-ui-stability`.

상태: **수정·로컬 검증 완료, Cloudflare 운영 미배포**. 현재 PC의 `wrangler whoami`는 미인증이다. 운영 DB·DNS·PG·랭크업 서버는 변경하지 않았다. 기존 회원 원본 대조와 비밀번호 호환 검증·보류 해제는 사용자가 “그건 나중에 할게”라고 답해 후속으로 남겼다.

## 아이디와 이전 회원 보존

- 신규 아이디: 영문·숫자로 시작하는 4~30자, 영문·숫자·밑줄·하이픈, 대소문자 구분. 연락 이메일은 복구·안내용 필수 항목이며 기존 이메일 로그인도 유지한다.
- 기존 rankup 아이디·비밀번호 해시·salt·iterations·보류 상태는 변경하지 않는다. 기존 아이디를 새 회원이 차지하지 못하도록 두 테이블 사이 충돌을 DB 트리거로 차단한다.
- 신규 아이디 삽입과 자격 증명·프로필·동의는 D1 batch 안에서 처리한다. 동시 중복 가입에서 한 건만 성공하고 실패 계정이 남지 않는지 확인했다.
- 아이디 기반 비밀번호 복구 조회와 아이디 안내 메일 대상 조회, 마이페이지·가입 완료 표시를 연결했다. 실제 메일 발송은 이번 검수에 포함하지 않았다.
- 기존 배포 폼 호환을 위해 API의 `loginId` 생략은 허용하되, 새 가입 화면은 아이디를 필수로 받는다. 기존 이메일 회원에게 아이디를 임의 발급하지 않는다.
- `drizzle/0022_native_login_ids.sql`은 새 테이블·충돌 방지 트리거만 추가한다. 백업 테이블 목록과 스키마 버전 0022, 탈퇴 정리를 함께 반영했다.
- 개인정보 처리 안내에 아이디를 포함하고 방침 버전을 `privacy-v1.4-2026-10-19`로 기록한다.

## 동의 화면

기본 화면은 `추가 정보 입력 (선택·접기)` → `필수 항목 모두 동의` → 이용약관·개인정보 안내·14세 이상 확인의 짧은 행으로 구성한다. 체크는 초기 선택하지 않는다. 필수 일괄 선택에는 선택 정보·마케팅을 포함하지 않는다. 목적·항목·보유기간·거부 안내와 전문 링크는 내용 보기에서 유지한다.

선택 정보 미동의 시 추가 입력을 비활성화한다. 이전에 입력한 값이 남아 있거나 API로 전달돼도 가입 필수 정보만 저장한다. 동의한 선택 정보는 별도 동의 스냅샷과 함께 저장한다. 이는 UI와 처리 로직 검수이며 법률 적합성 인증을 뜻하지 않는다.

## 운영 반영 전후

1. 이 PC에서 Cloudflare 운영 계정 인증을 완료한다. 현재 미인증 상태에서 임시 계정·다른 프로젝트에 대신 배포하지 않는다.
2. 기준 브랜치 및 Sites main의 동일 소스 SHA를 확인한다. Sites는 소스 미러이며 정식 운영 배포 대상이 아니다.
3. 운영 D1 백업과 복원 검증, 기존 30개 바인딩/운영 설정 대조를 수행한다. `medihelpers-staging`의 실제 DB는 production임에 주의한다.
4. 새 스키마는 마이그레이션 0022 또는 검증된 런타임 초기화로 적용한다. 기존 회원 해시·별칭·보류 상태를 건드리지 않는다.
5. `deploy/cloudflare.live-with-legacy-replies.json`으로 검증된 동일 소스를 배포한 뒤 `/jobs` 지연, 반복 조회 타이밍, 가입·아이디 로그인·역할별 권한, HTML no-store와 최신 자산을 확인한다.
6. 실제 기존 회원 인증은 사용자가 원본 자료 작업을 재개할 때 대조하고 활성화한다. 현재 변경으로 이전 완료라고 표시하지 않는다.
